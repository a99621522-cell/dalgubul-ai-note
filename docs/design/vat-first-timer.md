# 지자체 부가세 점검기 v2 설계 — 처음 맡은 공무원과 수탁기관이 함께 쓰는 흐름

> 구현 상태(2026-10-27): 1~3단계 모두 구현. 1단계 `/vat/`·`/vat/setup/`·`/vat/monthly/`, 2단계 `/vat/prepare/`, 3단계 붙여넣기(월간 기록 안)·`/vat/handover/`. 설계와 달라진 점 — 4.3 의 ②-1 '카드 부가세 구분' 질문 추가, 4.4 의 (13) 예정 누락분은 저장된 예정신고 기록과 견줘 자동(기록 없으면 기본 끔), 인수인계 zip 은 라이브러리 없이 브라우저가 묶는다(저장 전용). 세부는 CLAUDE.md.

운영자 지시 2026-10-27: "신고하는 공무원이 이 업무를 처음 맡았다고 생각하고 수탁기관과 공무원이 쉽게 효율적으로 사용할 수 있도록 설계해봐".
현재 `/vat/`(1차, 같은 날)는 '아는 사람이 한 건씩 확인하는 도구'다. v2 는 **모르는 두 사람이 자료를 주고받아 신고까지 가는 흐름**으로 바꾼다. 조문 근거는 `data/vat/rules.yml`(2026-10-27 원문 대조) 그대로 쓰고, 신고서 칸 번호는 시행규칙 별지 제21호서식(2026-04-01 시행 판, `data/guidelines/vat-rule.txt.gz`)에서 확인했다.

## 1. 누가, 무엇을 모르는가

| 사람 | 아는 것 | 모르는 것 | 지금 하는 일 |
|---|---|---|---|
| **A. 시설 담당·수탁기관 직원** | 어느 시설에 무슨 돈을 썼는지, 영수증 실물 | 과세·면세, 공제, 안분, 신고서 | 영수증을 모아 회계로 넘김(귀속 표시 없음) |
| **B. 신고 담당 공무원(처음)** | 홈택스 로그인, 회계 처리 | 시설 사정, 세법 용어, 어느 칸에 적는지 | 넘어온 영수증을 합계표에 옮기고, 애매한 것은 뺌 |

금액 차이는 A→B 로 넘어가는 자료에 **귀속(어느 시설·어떤 용도)** 과 **증빙 명의** 가 적혀 있느냐에서 난다(세무사를 써도 같다). 그래서 v2 의 중심 산출물은 신고서가 아니라 **A 가 매달 만드는 '매입 인계표'** 다.

## 2. 설계 원칙

1. **질문은 세법 용어가 아니라 현장 사실로.** "공통매입세액입니까?"가 아니라 "이 돈은 어디에 쓰였나요? ① 이 시설만 ② 여러 시설 ③ 사무실·행정과 함께 ④ 모름".
2. **역할별 입구 둘.** 시설 담당은 '기록', 공무원은 '설정·준비'. 서로의 화면을 볼 필요가 없다.
3. **한 번 정한 것은 다시 묻지 않는다.** 시설 목록·과세 여부·등록 단위는 공무원이 1회 설정 → 파일로 저장 → 수탁기관은 받아서 연다.
4. **모든 결과는 한글·엑셀로 나간다.** 인계표·신고 준비표·시설 카드. 공문에 붙이는 것이 끝이어야 한다.
5. **서버 없음을 지킨다.** 기관 간 공유는 JSON 파일(업무망 메일·공문 첨부)로. 개인정보(담당자 이름·전화)는 파일에 넣지 않고 부서명만.
6. **판정은 참고, 책임은 신고인.** 모든 화면 아래 같은 문장. 평가·순위 없음(사이트 원칙).

## 3. 화면 구조

```
/vat/                 시작 — "처음이세요?" 3분 그림 + 역할 선택 + 이번 마감 D-day
├─ /vat/setup/        ① 기관 설정 마법사 (B, 처음 1회·시설 바뀔 때)  → org.json, 시설 카드(한글)
├─ /vat/monthly/      ② 시설 지출 기록 (A, 매달)                      → ledger-<시설>-<YYYYMM>.json, 매입 인계표(한글·CSV)
├─ /vat/prepare/      ③ 신고 준비 (B, 예정·확정 때)                   → 신고서 칸별 숫자표, 첨부 목록, filing-<기간>.json
├─ /vat/handover/     ④ 인수인계 꾸러미 (B, 담당 바뀔 때)             → 설정+기록+자산대장 zip
└─ /vat/tools/        기존 1차 도구(지출 건 판정·안분·재계산·시설표·점검표) — 아는 사람용으로 유지
```

## 4. 흐름 상세

### 4.1 시작 화면 `/vat/`
- 맨 위 한 장 그림(인라인 SVG): **이용자 → 시설 수입(매출세액) / 시설 지출(매입세액) → 매입세액을 빼고 남는 것을 낸다 → 지출이 어느 시설 것인지 적혀 있어야 뺄 수 있다.** 글자 60자 이내.
- 단추 둘: 「시설을 운영합니다(수탁기관·시설 부서)」 → ②, 「신고를 맡았습니다(회계·세무 담당)」 → 설정 파일이 있으면 ③, 없으면 ①.
- 띠: 다음 신고 기한과 D-day(법 제48조·제49조 날짜표), 이번 달 인계표 마감(기관 설정에서 정한 날, 기본 다음 달 5일).
- 「3분 안내」 펼침: 신고 흐름 4단계(등록 → 발급 → 수취 → 신고)와 '누가 무엇을' 표(1절 표를 쉬운 말로).

### 4.2 기관 설정 마법사 `/vat/setup/` (B, 5문항)
| 문항 | 보기 | 뒤에서 정해지는 것 |
|---|---|---|
| Q1 우리 기관이 돈을 받는 시설을 모두 고르세요 | 시설 유형 15개 그림 타일(`rules.yml facilities`) + 직접 추가 | 시설별 과세·면세·확인(근거 조문 자동) |
| Q2 시설마다 이름과 운영 방식 | 직영 / 위탁 — **군 명의 사업**(수탁기관은 대행) / 위탁 — **수탁기관 자기 사업** | 셋째면 "우리 신고가 아닙니다, 수탁기관이 신고" 표시하고 기록 대상에서 뺌 |
| Q3 사업자등록 | 등록번호, 사업장별 / 사업자 단위(법 제8조 제3항), 모르면 '홈택스 → 사업자등록 상태 조회' 안내 | 세금계산서 '공급받는 자' 번호, 안분 분모 단위 |
| Q4 시설별 수입 종류 | 세금계산서 발급(기관·법인 이용자) / 카드·현금영수증(개인) / 보증금 있음 | 신고서 (1)(3)(4)칸 배정, 간주임대료 계산 대상 |
| Q5 담당 부서와 인계 마감일 | 부서명(개인 이름 없음), 매달 N일 | 인계표 머리글, D-day |

산출: `org.json`(아래 5절) + **시설 카드**(시설마다 한글 한 장: 이 시설은 과세/면세, 세금계산서는 이 번호로 받으세요, 매달 할 일 4가지, 하면 안 되는 것 3가지, 문의 부서) → 수탁기관에 공문으로.

### 4.3 시설 지출 기록 `/vat/monthly/` (A, 매달)
- 열기: `org.json` 끌어다 놓기(또는 브라우저에 지난번 것 남아 있음) → 시설 고르기 → 달 고르기.
- 한 건 넣기(화면 질문 그대로):
  1. 날짜 · 내용 · 금액(공급가액·세액은 영수증에서 — "부가세 칸이 따로 있나요?")
  2. **영수증이 어떤 것인가요** — 그림 6: 전자세금계산서 / 종이 세금계산서 / 신용카드 전표 / 현금영수증 / 계산서(면세) / 없음·간이영수증
  3. **받는 사람 이름이 누구로 돼 있나요** — 우리 군(설정의 등록번호 보여 줌) / 공단·수탁기관 / 개인 / 모름(영수증 어디를 보는지 그림)
  4. **이 돈은 어디에 쓰였나요** — 이 시설만 / 여러 시설 / 사무실·행정과 함께 / 모름
  5. **무엇을 샀나요** — 전기·가스·통신 / 청소·경비·용역 / 수선·공사 / 비품·장비 / 차량(승용·승합 구분 그림) / 식사·선물 / 보험·급여·세금 / 토지 / 기타
- 자동: `vat_check.ts judge()` 로 판정 → **신호등** 초록(공제) · 파랑(공통 — 신고 때 안분) · 빨강(불공제) · 회색(세액 없음) · 노랑(확인) + "지금 할 일" 한 줄(예: 공단 명의면 "공급받는 자를 군 등록번호로 수정세금계산서 요청 — 이번 달 안에") + 조문 링크는 접힘.
- 고정자산(수선·공사·장비 중 자본적 지출) 체크 → 신고서 (12)/(45)칸 구분과 자산대장(재계산용) 행 생성.
- 대량 입력: 홈택스 '전자세금계산서 매입 목록' 내려받기(엑셀)나 카드사 명세를 **붙여넣기** → 열 맞추기(날짜·공급자·공급가액·세액·받는 자 번호) → 각 행에 4번·5번 질문만 답하게.
- 월말: 「매입 인계표 만들기」 → 표(시설·날짜·내용·공급가액·세액·증빙·받는 자·귀속·판정·할 일·근거)를 한글 표 복사·CSV + `ledger-<시설>-<YYYYMM>.json`. 빨강·노랑이 남아 있으면 머리에 "처리 안 된 N건" 경고.

### 4.4 신고 준비 `/vat/prepare/` (B, 예정·확정 때)
- 열기: `org.json` + 인계표 JSON 여러 개 끌어다 놓기 → 기간 자동 판정(1기 예정 1~3월 …), 빠진 시설·빠진 달을 표로.
- **집계 — 신고서 칸별 숫자표**(별지 제21호서식, 2026-04-01 판 확인):

| 칸 | 이름 | 들어가는 것 |
|---|---|---|
| (10) | 세금계산서 수취분 일반매입 | 초록 판정 중 세금계산서, 고정자산 아님 |
| (12) | 세금계산서 수취분 고정자산매입 | 초록 중 세금계산서, 고정자산 |
| (13) | 예정신고 누락분 | 확정신고 때 예정 기간 인계표에서 뒤늦게 온 것 |
| (15)→(44)/(45) | 그 밖의 공제매입세액 — 신용카드매출전표등 수령명세서 제출분 일반/고정자산 | 초록 중 카드·현금영수증 |
| (15)→(48) | 과세사업전환 매입세액 | 자산대장에서 면세→과세 전환 표시한 것(법 제43조) |
| (17)→(53) | 공제받지 못할 매입세액 | 빨강 판정 전부(토지·승용차·접대·면세사업·명의 다름) |
| (17)→(54) | 공통매입세액 중 면세사업등 해당 세액 | 파랑 판정 × 면세비율(아래 안분) |
| 매출 (1)/(3)/(4) | 세금계산서 발급분 / 카드·현금영수증 발행분 / 기타 | 시설별 수입(설정 Q4) — 간주임대료는 (4) |

- **안분 단계**: 파랑 합계가 있으면 시설(사업장) 단위로 "이번 기간 과세 수입·면세 수입(면세사업 보조금 포함)"을 묻고 `common` 계산기를 돌린다. 생략 기준(5%·500만 원·5만 원) 자동. 확정신고면 예정신고 때 값을 불러와 정산액을 보여 준다(시행령 제81조 제1항 단서).
- **재계산 알림**: 자산대장에 있는 건물·장비의 취득 때 면세비율과 이번 비율 차가 5%p 이상이면 `recalc` 계산기로 금액 제시(시행령 제83조).
- 산출: 「홈택스에 적을 숫자표」(칸 번호·금액·세액, 한글·CSV) + 첨부 서식 목록(매입처별 세금계산서합계표, 신용카드매출전표등 수령명세서, 공제받지 못할 매입세액 명세서, 공통매입세액 안분계산 내역, 부동산임대공급가액명세서) + 점검표 13개 중 자료로 확인되는 것 자동 체크 + `filing-<기간>.json` 저장.

### 4.5 인수인계 꾸러미 `/vat/handover/`
- `org.json` + 최근 4개 과세기간 `filing-*.json` + 자산대장 + "아직 처리 안 된 것" 목록 + 1쪽 안내("이 기관의 부가세는 이렇게 돌아간다")를 zip 으로. 다음 담당자는 `/vat/`에서 이 zip 하나를 열면 설정이 끝난다.

## 6. 말 바꾸기 표 (화면에는 왼쪽만, 오른쪽은 펼침·툴팁)

| 화면 질문 | 세법 용어 | 근거 |
|---|---|---|
| 이 돈은 어디에 쓰였나요 | 실지귀속 / 공통매입세액 | 법 제40조, 영 제81조 |
| 받는 사람 이름이 누구인가요 | 세금계산서 필요적 기재사항(공급받는 자 등록번호) | 법 제32조, 제39조 제1항 제2호 |
| 영수증이 어떤 것인가요 | 세금계산서 / 신용카드매출전표등 / 계산서 | 법 제46조 제3항 |
| 부가세 칸이 따로 있나요 | 부가가치세액 별도 구분 | 법 제46조 제3항 |
| 이 시설 수입 중 세금 안 붙는 수입 | 면세공급가액(보조금 포함) | 영 제81조 제1항 단서 |

## 7. 판정 규칙에 더할 것 (`rules.yml`·`vat_check.ts`)
- `run: entrusted_own`(수탁기관 자기 사업) 시설은 기록 화면에서 "이 시설의 부가세는 수탁기관이 신고합니다 — 군 매입세액 아님"으로 막는다.
- `payee` 질문 추가(현재는 증빙 보기에 섞여 있음): `contractor` → 불공제 + 수정세금계산서 할 일, `person` → 불공제, `unknown` → 노랑.
- `asset: true` → 칸 (12)/(45) 배정, 자산대장 행, 재계산 추적.
- `use: multi`(여러 과세 시설) 와 `admin`(행정과 함께)을 나눈다: multi 는 같은 사업장 안 과세 시설끼리면 전액 공제(면세 없음), admin 은 공통.
- 인계표에서 `done` 체크(수정세금계산서 받음 등)가 되면 판정을 다시 돌린다.

## 8. 마감·알림(서버 없음)
- 시작 화면과 기록 화면 머리에 D-day 띠: 신고 기한(법 제48조·제49조) / 인계 마감(설정) / 전자세금계산서 전송 기한(다음 달 11일, 법 제54조 제2항).
- 브라우저 알림·메일은 없다(서버 없음). 대신 시설 카드와 인계표 머리에 "다음 할 일과 날짜"를 인쇄해 둔다.

## 9. 한계와 지키는 것
- 서버·계정이 없어 기관 간 공유는 파일이다. 파일에 개인정보를 넣지 않는다.
- 판정은 입력한 보기만으로 한다(계약 내용·유권해석은 담당자). '유권해석·분류 확인' 항목은 노랑으로 남긴다.
- 사이트 원칙대로 평가·순위 없음, 기관별 신고 금액은 싣지 않는다(저장은 각자 브라우저·파일).
- 신고서 칸 번호는 서식 개정 때 바뀐다 — `rules.yml` 에 `form: { ver: "2026-04-01", cells: {...} }` 로 두고 서식이 바뀌면 거기만 고친다.

## 세무사 관점 평가와 보강(2026-10-27, 운영자 '30년 넘는 세무사 입장에서 평가해봐' → '제안한 순서대로 해봐')
