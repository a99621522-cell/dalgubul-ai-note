## 1. 무엇을 만들었나

결과 화면의 「세무서 제출 묶음 받기」(`#rf-dl-cases`)와 두 큰 묶음(`#rv-zip`·신고서만 묶음)의 앞부분이 같은 꾸러미를 준다. 앞 번호 = 붙임 번호.

| 파일 | 누구에게 | 내용 |
|---|---|---|
| 00 할 일 | 기관 | 7단계(증빙 받기 → 제출 전 확인 관문 → 결재 → 사전 상담 → 서명·계좌 → 제출 → 그 뒤), 과장 보고 3줄, 나중 묶음, 낱말 풀이 |
| 01 검토 요약서 | 세무서·결재 | 청구 요지, 과세기간별 당초 → 경정 후, 쟁점(금액 큰 순), 3-1 당초 신고서 과세표준 명세(업종코드), 먼저 밝히는 것(이번에 뺀 몫), 붙임 |
| 02 경정청구서 | 세무서 | 별지 제16호의2서식 — 1·2등급만, 신고서 파일 이름·안내 쪽·바닥 문구 없는 판 |
| 03 사유서 | 세무서 | 신고서별 이유·고친 칸(공통매입세액 안분 계산 줄 포함)·근거 법령·붙임 |
| 04 재계산표 | 세무서 | 청구하는 신고서 시트와 건별 근거만(공무원용 '먼저 읽기·확인할 것·쉬운 말·검토란' 없음) |
| 05 공제로 옮기는 세금계산서 | 세무서 | 공급자별, '당초 신고(16)에 들어 있음 — 합계표 추가 제출 대상 아님' 표시 |
| 06 세금계산서별 시설 귀속 | 세무서 | 청구한 행만, 공급받는자 등록번호 |
| 07 근거 발췌 | 세무서 | 청구를 받치는 조문·유권해석만 |
| 08 부서별 증빙 요청 메모 | 기관 | 부서별로 묶음, 서류마다 해당 시설 |
| 09 사전 상담 대본 | 기관 | 3분 — 먼저 밝힐 것, 물을 것, 받은 답 빈칸 |
| 10 보완 요청 답변 틀 | 기관 | 질문 29개 답(확인 못 한 사실은 '[확인 후 기재: …]') |
| 11 질의서 초안 | 기관 | 4등급 쟁점 |
| 12 수정신고 함께내기 비교 | 기관 | 3등급 — 돌려받을 몫 − 매출세액 − 가산세, 감면율·감면 예외 |
| 13 내부 작업서 | 기관 | 모든 등급의 신고서별 계산·확인할 것·법령 검토·세무서가 볼 것·쟁점 등급 |

등급(`vat_casebook.ts caseIssues`): 1 계산 정정 · 2 증빙으로 끝남 → 이번 청구 / 3 매출과 함께 · 4 해석 다툼 → 나중 묶음. 기준은 질문 은행 문서. `caseCorrDocs`·`caseBook` 에 `pick`(등급 고르기)을 주면 02·03·04 가 같은 금액이 된다.

## 2. 세 역할 시험

하위 에이전트가 역할만 받고 묶음 파일만 읽었다(질문 은행·앱 설명은 주지 않음).

| 역할 | 결과 | 받아들여 고친 것 |
|---|---|---|
| B 조사관 | 자료 보완 요청 13항목 | 05 '추가분'이 이미 신고된 세금계산서라 이중 공제로 읽힘 → 이름·뜻 바꿈 / 23-1기 안분 계산 줄이 없음 → 03·04 에 명세서 안분 줄 / 01 이 2017두55329 를 근거로 들어 자기 계산을 흔듦 → 제출 문서에서 뺌 / 당초 '②'로 분류한 경위 → 01 쟁점 문장 / 과세표준 명세 업종 → 01 3-1 / 06 의 보류 시설 '전액 공제' 모순 → 청구 행만 / 시행규칙 제35조 인용 취지 불명 → 뺌 |
