# 지자체 부가세 절감 점검기 — 공무원 사용자 리서치 (2026-10-28)

프롬프트 `docs/prompts/vat_ux_civil_servant.md` 1절. 조사 대상은 `/vat/` 12개 화면(2026-10-28 main 기준, 커밋 95a80e1). 실제 사용자 조사는 운영자(현직 지방공무원) 몫이므로 여기서는 **가정 기반 페르소나·과업 분석**, **측정 가능한 before 지표**, **운영자가 돌릴 수 있는 조사 스크립트**를 남긴다. 평가·권고가 아니라 설계(`vat-ux-spec.md`)의 입력이다.

## 3. 과업 분석(HTA) — 확정신고 준비

```
0. 제N기 확정신고서 숫자 만들기 (기한: 7/25 또는 1/25)
 ├─ 1. 자료 확인
 │   ├─ 1.1 기관 설정이 이 브라우저에 있는지 [자동: localStorage] 없으면 org.json 열기 [수동]
 │   ├─ 1.2 과세기간 6개월 × 시설마다 기록이 있는지 [자동: 도착 현황표] 빈 칸은 시설 담당에게 요청 [수동·시스템 밖]
 │   └─ 1.3 예정신고 기록(filing)이 있는지 [자동] 없으면 예정 값 4칸 입력 [수동]
 ├─ 2. 매출 입력 (과세·확인·유상 수탁 시설마다)
 │   ├─ 2.1 (1)(3)(4) 공급가액 [수동: 홈택스 매출 집계에서]
 │   └─ 2.2 보증금 시설이면 간주임대료 [반자동: 보증금·이자율 입력 → 계산]
 ├─ 3. 안분 (등록 단위마다)
 │   ├─ 3.1 면세 공급가액 [수동] · 일회성 면세(토지 매각) [선택]
 │   ├─ 3.2 안분 기준 [자동 판단: 과세·면세 둘 다 있으면 공급가액 비율로 잠금 / 한쪽 없으면 제4항 순서 선택 수동 / 건물 신축이면 면적 우선]
 │   ├─ 3.3 본청·행정 공통 기준 [수동 — 유권해석 확인, 없으면 (54) 미반영 경고]
 │   └─ 3.4 예정 정산 [자동: 저장 기록] 
 ├─ 4. 예외 분기 [자동 판정, 수동 결정]
 │   ├─ 4.1 예정고지 대상인가 (직전 과세기간 공급가액 < 1억 5천만) [자동]
 │   ├─ 4.2 공통 자산 재계산 해당 (면세비율 5%p 변동) [자동 계산, 적용은 신고인]
 │   ├─ 4.3 과세사업 전환 자산 [수동 입력 → 자동 계산]
 │   └─ 4.4 처리할 것: 노랑·다른 명의·증빙 없음·지연 수취·보조사업 [자동 목록, 각각 수동 조치]
 ├─ 5. 숫자표·서식 7종 [자동] → 홈택스에 옮겨 적기 [수동·시스템 밖]
 └─ 6. 신고 기록 저장(filing JSON + localStorage) [수동 1클릭] → 다음 기수 재계산·예정고지 판단의 입력 [자동]
```

설계 함의: 자동으로 정할 수 있는 것(1.1~1.3, 3.2 잠금, 3.4, 4.1, 4.2, 5)은 **묻지 않고 보여 주기만** 하고, 사용자가 정해야 하는 것(2.1, 3.1, 3.3, 4.3, 4.4의 조치)을 4단계 위저드의 단계로 삼는다. 4.4는 결과의 맨 위(exception-first)에 둔다.

## 4. 사용성 조사 설계(운영자 실행)

- 참가자: 운영자 1인(A형) + 가능하면 공단 회계 담당 1인(B형). 세션 40분, 화면 녹화 대신 관찰자가 기록 시트에 적는다. 개인정보·기관 실제 금액은 쓰지 않고 **예시 값**(달성군 예시 설정, 아래 샘플 붙여넣기)을 쓴다.
- 방법: think-aloud(생각을 소리 내며 수행). 관찰자는 돕지 않고 막힘이 2분을 넘을 때만 "다음에 무엇을 하겠습니까"라고 묻는다.
- 지표: 과업 성공률(독립 완료 / 힌트 뒤 완료 / 실패), 과업 시간(초), 오류 수(잘못 누른 단추·되돌린 입력), 과업마다 SEQ(1~7 "이 과업은 얼마나 쉬웠습니까"), 끝에 SUS 10문항(0~100).
- 과업 5개(순서 고정):

| T | 지시문(참가자에게 그대로 읽어 줌) | 성공 기준 | 시작 화면 |
|---|---|---|---|
| T1 | "우리 기관은 달성군이라고 치고, 시설 목록을 예시로 불러와서 '달성군민체육관'의 운영 방식을 '우리 기관이 직접 운영'으로 정하고 설정 파일을 내려받으세요." | org.json 내려받음, 그 시설 run = direct | /vat/ |
| T2 | "이 표(샘플 20행)를 10월 지출로 기록하세요. 모두 체육관 지출이고 '이 시설만' 쓴 것입니다." | 기록 20건, use = this | /vat/monthly/ |
| T3 | "2026년 제2기 예정신고에 적을 숫자를 만들고 신고 기록을 저장하세요. 체육관 카드 매출은 3,000,000원입니다." | filing 저장, (3)=3,000,000 | /vat/prepare/ |
| T4 | "방금 결과에서 '지금 처리해야 할 것'이 몇 건인지 말해 주세요." | 처리할 것 건수를 맞게 말함(30초 안) | 결과 화면 |
| T5 | "후임자에게 넘길 꾸러미를 만들고, 새 창(시크릿)에서 그 꾸러미를 열어 설정이 되살아나는지 확인하세요." | zip 내려받기 + 복원 뒤 시설 수 일치 | /vat/handover/ |

- 기록 시트(과업마다 한 줄): 시작 시각 / 끝 시각 / 결과(독립·힌트·실패) / 오류 수 / 막힌 곳(화면·요소) / 참가자 말 그대로 1~3개 / SEQ. 끝에 SUS 10문항 점수와 "가장 헷갈린 낱말 3개".
- 분석: 과업별 성공률·중앙값 시간을 before 표에 적고, 막힌 곳은 휴리스틱 표의 심각도를 올리는 근거로 쓴다.

## 6. 결론(설계 입력)

1. 입력 비용은 두 화면(설정 3단계·붙여넣기 미리보기)에 몰려 있다 → 그리드·일괄 적용·자동 귀속 뒤 미확정만 보이기로 **클릭을 1/4, 노출 필드를 1/5**로.
2. 상태 가시성(다음 할 일·저장·진행)이 없어 처음 맡은 사람이 "어디까지 했나"를 모른다 → 대시보드·문맥 바·stepper.
3. 예외(처리할 것)가 결과 아래에 있어 신고 전날에야 본다 → exception-first.
4. 용어가 흔들린다 → 용어 사전 한 벌과 '현장 말 — 법령 용어' 표기.
5. 색만으로 뜻을 전하는 곳과 alert 가 접근성·오류 복구를 해친다 → 아이콘·인라인 검증·undo.
