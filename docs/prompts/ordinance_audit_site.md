# 프롬프트 — 대구 자치법규 정비 검토 사이트: 상위법령 변경·폐지 뒤 정비되지 않은 조례·규칙 찾기

작성 2026-10-08(운영자 요청: '대구시와 9개 구·군 자치법규 중 상위법령이 바뀌거나 폐지됐는데 정비되지 않은 것, 법제처에 비슷한 질의가 있었던 것, 상위법령과 맞지 않아 보이는 것을 찾아 정비하는 사이트'). **이 문서는 실행 지시가 아니라 새 세션에 줄 프롬프트**다. 아래 '---' 밑을 통째로 새 세션 첫 메시지로 붙인다.

## 붙이기 전에 운영자가 정할 것 세 가지

| 결정 | 권장 | 이유 |
|---|---|---|
| 어디에 만들까 | **새 저장소·새 주소**(예: `law.daitda.co.kr`) | 이 저장소는 '대구 산업' 사이트라 범위가 다르다. 법령 수집 코드(`scripts/fetch_guidelines.py`의 law.go.kr DRF 호출)·표 도구(`table_tools.ts`)·한글 내보내기만 복사해 쓴다 |
| 누구에게 보일까 | **처음엔 비공개(검색 제외 noindex + 주소 아는 사람만)**, 표본 검증 뒤 공개 여부 결정 | 운영자가 현직 공무원이다. 자기 기관·다른 구·군의 '정비 안 된 조례 목록'은 기관 비판으로 읽힐 수 있다. 공개해도 '검토 후보'라는 중립 표현만 쓴다 |
| 법제처 오픈API 키 | open.law.go.kr 에서 OC 신청 → GitHub Secrets `LAW_OC` | 게스트 `test` 로도 되지만 호출량·일부 API(연계·연혁)는 신청해야 열린다 |

> 겸직·정보 공개 관련 소속 기관 규정은 운영자가 따로 확인한다(이 프롬프트 범위 밖).

# 역할
당신은 (1) 자치법규 입안·심사 실무자(지방자치법 제28조·제29조, 법제처 「자치법규 입안 길라잡이」 수준), (2) 국가법령정보센터 오픈API(law.go.kr/DRF) 데이터 엔지니어, (3) Astro 정적 사이트 개발자다. 운영자는 대구의 현직 지방공무원이다. 목표는 **대구광역시와 9개 구·군(중구·동구·서구·남구·북구·수성구·달서구·달성군·군위군)의 조례·규칙 가운데 상위법령 변경·폐지에 맞춰 정비되지 않았을 가능성이 있는 조문을 근거와 함께 찾아, 담당자가 바로 정비안(신구조문대비표)을 만들 수 있게 하는 사이트**다.

# 절대 원칙 (코드·문구·프롬프트 모두에 유지)
1. **판정하지 않는다.** 사이트는 '위법'·'무효'·'잘못'·'방치'·'미정비 기관' 같은 말을 쓰지 않는다. 모든 결과는 **'정비 검토 후보'** 이고, 신호 종류·근거 원문·확인 방법만 보인다. 맨 위 고정 안내: "자동 대조 결과이며 법적 판단이 아닙니다. 정비 여부는 소관 부서·법무 담당·법제처 검토로 정합니다."
2. **원문 그대로, 출처·기준일 항상.** 조례 조문과 상위법령 조문은 국가법령정보센터 원문을 그대로 인용하고 링크·시행일·받은 날을 붙인다. 원문에 없는 날짜·조문 번호를 만들지 않는다. 모르면 "원문 확인 필요".
3. **순위·비교 평가 없음.** 지자체별 건수 표는 행정 순서(대구시 → 중·동·서·남·북·수성·달서·달성·군위)로만, 정렬·'최다'·'TOP' 금지. 지자체끼리 '정비율' 같은 지표를 만들지 않는다.
4. **공개 자료만.** 국가법령정보센터·자치법규정보시스템(ELIS)·법제처 공개 해석례·판례만. 의회 내부 자료·비공개 검토 의견·담당자 이름·전화는 수집하지 않는다. 사이트 robots.txt 와 이용 약관을 지키고 요청 사이 1초 이상.
5. **AI 는 보조만.** 규칙으로 찾은 후보에 대해 AI(Gemini 등)를 쓰면 '확인 메모' 초안까지만, `approved: false` 로 저장하고 운영자 승인 뒤에만 보인다. AI 가 단독으로 후보를 만들거나 위배 여부를 단정하지 않는다.
6. 외부 API 실패는 로그만 남기고 건너뛴다(무인 실행). 이 세션 환경은 law.go.kr 이 막혀 있을 수 있으므로 **수집은 GitHub Actions 러너**가 하고 결과를 커밋한다.

# 1. 데이터 수집 (먼저 API 를 실측하고 표로 보고)
open.law.go.kr 의 '오픈API 활용가이드'를 먼저 읽고, 아래 각 항목에 실제 `target` 값·요청 인자·응답 태그를 **러너에서 probe 로 확인해** `docs/api.md` 에 표(용도 · target · 인자 · 주요 태그 · 확인일)로 남긴다. 추측한 이름으로 코드를 쓰지 않는다.

| 용도 | 출처(확인할 것) |
|---|---|
| 자치법규 목록·본문 | DRF `target=ordin` — 지자체 기관코드(`org`)·종류(조례/규칙)로 10개 지자체 전체 현행 목록, 본문은 조문 단위(조 번호·제목·항·호·부칙·별표·제정/개정일·시행일·소관부서) |
| 법령 현행 본문 | `target=law`(현행), `eflaw`(시행일 기준) |
| 법령 연혁·제명 변경·폐지 | 법령 연혁 목록(`lsHistory` 계열), 폐지 법령, 조문별 변경 이력 API(있으면) |
| 신구조문 | 신구법 비교 API(있으면) |
| **법령 ↔ 자치법규 연계** | 법령별 위임 자치법규·자치법규별 근거 법령 연계 API(가이드의 '연계' 항목) — 있으면 2절 인용 파싱보다 우선 |
| 위임 조문 | 법령의 '조례로 정한다' 위임 조문(위임법령 API 또는 본문 검색) |
| 법제처 해석 | 법령해석례 `target=expc`(지자체 질의 포함), 자치법규 관련 의견제시 사례(ELIS 또는 법제처 공개 목록 — API 없으면 목록 페이지, robots 확인) |
| 판례 | `target=prec`(조례 무효·위임 범위 판결), 헌재 `detc` |
| 행정규칙 | `target=admrul`(행안부 자치법규 정비 지침·예규 — 공개분만) |

- 저장: `data/ordin/<org>/<자치법규ID>.json`(조문 배열), `data/laws/<법령ID>.json`(현행 + 연혁 요약), `data/expc/*.json`. 큰 본문은 gzip.
- 워크플로 `fetch.yml`: 매주 월 03:00 KST + 수동. 바뀐 것만 다시 받는다(자치법규 개정일·법령 시행일 비교). 첫 실행 뒤 지자체별 자치법규 건수를 `data/summary.md` 에 기록.
- 군위군은 2023-07-01 경상북도 → 대구광역시 편입이므로 편입 전 경북 소속으로 제·개정된 자치법규가 섞인다. 기관코드가 바뀌었는지 실측해 두 코드를 모두 받는다.

# 2. 인용 파싱 — 조례가 기대는 상위법령 조문 찾기
`scripts/extract_refs.py` → `data/refs.csv`(자치법규ID · 조문 · 인용 법령명(원문 표기) · 법령ID · 조·항·호 · 인용 유형).
- 패턴: 「○○법」 제n조제m항제k호, 「같은 법 시행령」, '법'·'영'·'규칙' 약칭(그 조례 제2조 정의나 제1조 목적에서 풀이), '같은 조', '이 법', 별표 인용, '○○법령에서 정하는 바에 따라'.
- 인용 유형: 근거(목적 조항의 '위임된 사항') / 정의 차용 / 절차 준용 / 기준값 인용.
- 법령명 → 법령ID 매칭: 현행 제명, 옛 제명(연혁), 띄어쓰기 차이를 모두 시도. 실패한 인용은 `unresolved` 로 따로 세어 보고(파서 품질 지표).
- 연계 API 가 있으면 그 결과와 파싱 결과를 대조해 차이를 보고한다.

# 3. 정비 검토 신호 (규칙, `config/signals.yml` 에 정의)
신호마다 `key · 이름 · 판정 규칙 · 근거로 보일 것 · 확인 방법 · 자동 정비안 가능 여부` 를 적는다. 최소 아래 12개.

| key | 신호 | 규칙 요지 |
|---|---|---|
| `law_repealed` | 근거 법령 폐지 | 인용 법령이 폐지됨(폐지일, 대체 법령이 연혁에 있으면 함께) |
| `law_renamed` | 법령 제명 변경 | 인용 제명이 옛 이름 |
| `article_moved` | 조문 번호 이동 | 인용 조·항이 현행 법령에 없거나 '삭제', 또는 같은 내용이 다른 번호로 옮겨 감(신구조문·조문 이력으로 확인). 예: 2022-01-13 시행 지방자치법 전부개정 전 조문 번호 인용 |
| `article_changed` | 근거 조문 내용 변경 | 근거 조문의 개정 시행일 > 조례 최종 개정일, 그리고 위임 문구(대상·기준·범위)가 바뀜. **개정됐다는 사실만으로는 후보가 아니다** — 조문 글자 차이를 보여 준다 |
| `delegation_missing` | 위임 받은 조례 없음 | 상위법령에 '시·도(시·군·구) 조례로 정한다'가 있는데 그 지자체에 대응 자치법규가 없음(같은 위임을 받은 다른 지자체 조례가 있는 경우에만, 예시로 제시) |
| `number_mismatch` | 기준값 차이 | 상위법령 숫자(과태료 상한, 위원 수, 기간, 금액·비율)와 조례 숫자 비교. 상한 초과·하한 미달만 |
| `term_outdated` | 옛 용어·기관명 | 법령 일괄 용어 정비 목록(예: 기관명 변경, 장애 관련 용어, 한자어 순화)과 대조. 목록은 법령 개정 이유문에서 근거를 붙여 `config/terms.yml` 로 |
| `rights_no_delegation` | 권리 제한·의무 부과의 법률 위임 확인 | 지방자치법 제28조 단서 — 벌칙·과태료·의무·제한 문구가 있는데 2절에서 법률 위임 근거 인용을 못 찾음. **'확인 필요'로만**, 판정 금지 |
| `penalty_basis` | 과태료·벌칙 근거 | 과태료 조항의 근거 법률·상한(지방자치법 관련 조문, 실측 인용) 확인 |
| `sunset` | 유효기간 지남 | 부칙·본문의 유효기간·한시 규정이 지났는데 현행으로 남아 있음 |
| `peer_amended` | 같은 쟁점 다른 지자체 개정 | 같은 상위 조문을 근거로 하는 전국 자치법규 다수가 그 조문 개정 뒤 개정됐는데 이 자치법규는 아님(대구 10곳 + 전국 같은 제명 검색, 몇 곳 중 몇 곳만 숫자로) |
| `expc_related` | 관련 법제처 해석·판례 | 같은 상위 조문·같은 쟁점의 법령해석례·자치법규 의견제시·판례가 있음(참고 링크, 결론 요약은 원문 15단어 이내 인용) |

- 군위군 편입 관련(`merged_gunwi`): 경상북도·경북 기관명·경북 조례 인용이 남은 군위군 자치법규.
- 후보마다 `confidence`: `auto`(기계적으로 확정되는 사실 — 폐지·제명·번호 이동·유효기간) / `check`(사람 확인 필요 — 내용 변경·위임·기준값·권리 제한). 화면에서 둘을 구분한다.
- 결과: `data/candidates.csv`(후보ID · 지자체 · 자치법규 · 조문 · 신호 · confidence · 조례 원문 · 상위법령 현행 원문 · 변경일 · 근거 링크 · 정비안 가능).

# 4. 정확도 검증 (사이트에 띄우기 전 필수)
- 신호별로 무작위 표본(신호당 30건, 적으면 전부)을 뽑아 `data/eval/sample.csv` 로 내보내고, 운영자가 '맞음/아님/모름'을 표시할 수 있게 한다(Word·한글로 받을 수 있는 표).
- 세션이 먼저 원문을 읽고 자기 판단 칸을 채워 두되, 운영자 표시가 최종이다. 신호별 정밀도를 `docs/eval.md` 에.
- **정밀도 80% 미만 신호는 사이트에 노출하지 않는다**(`signals.yml` 의 `show: false`). 틀린 사례는 규칙을 고칠 근거로 남긴다.
- 이미 정비된 것을 후보로 잡는 오류(예: 최근 일괄 개정 반영)를 막기 위해 '자치법규 개정일 ≥ 상위법령 시행일' 이고 글자도 반영됐으면 후보에서 뺀다.

# 5. 정비안 초안 (기계적 신호만)
- `law_renamed`·`article_moved`·`term_outdated`·`merged_gunwi` 처럼 글자 바꿈으로 끝나는 신호는 **신구조문대비표 초안**(현행 | 개정안, 바뀐 글자 밑줄)을 자동으로 만든다. 여러 신호가 한 자치법규에 있으면 한 표로 묶는다.
- 일괄 정비 묶음: 같은 상위법령 변경으로 여러 자치법규가 걸리면 '○○법 개정에 따른 ○○ 등 n건 일괄 정비' 묶음 페이지(일괄개정 조례안 초안 형식).
- 내려받기: 한글 표 복사(클립보드 HTML+TSV, 기존 `table_tools.ts` 방식), Word(.docx), PDF. HWPX 는 한글 실물 시험 통과 전까지 내지 않는다(다잇다 노트의 관문 방식 그대로).
- 초안 머리에 "자동 생성 초안 — 조문 체계·부칙(시행일·경과조치)은 입안 담당자가 작성" 문구. 부칙·경과조치는 만들지 않는다.
- 내용 판단이 필요한 신호(`article_changed`·`delegation_missing`·`number_mismatch`·`rights_no_delegation`)는 정비안을 만들지 않고 '확인할 것' 목록(상위 조문 신구 대비, 같은 쟁점 다른 지자체 조문 예시, 관련 해석례)만.

# 6. 사이트 (Astro 정적, 서버·AI 호출 없음, 검색은 브라우저 색인)

# 7. 수용 기준
① 10개 지자체 현행 자치법규 전체를 받았고 건수가 국가법령정보센터 검색 건수와 맞음(차이는 사유와 함께 보고) ② 인용 파싱 해석률(법령ID 로 이은 인용 ÷ 전체 인용) 보고, 목표 95% ③ 신호 12개+군위 1개가 `signals.yml` 에 있고 신호별 후보 수 보고 ④ 표본 검증 표와 신호별 정밀도, 80% 미만은 숨김 ⑤ 기계적 신호의 신구조문대비표 초안이 원문 글자와 정확히 대응(자동 대조 테스트) ⑥ 화면·파일 어디에도 금지 낱말(위법·무효·방치·미정비 기관·순위·TOP·최다) 없음 — 빌드 검사 스크립트로 확인 ⑦ 담당자 이름·전화 0건 ⑧ 주간 워크플로 녹색, 변경분만 다시 받음 ⑨ `CLAUDE.md` 에 구조·원칙·명령 기록.

# 순서
1절 API 실측(probe 워크플로) → 수집 → 2절 파싱·해석률 보고 → 3절 신호(`auto` 신호 먼저: 폐지·제명·번호 이동·유효기간·군위) → **4절 표본을 운영자에게 넘기고 멈춤** → 운영자 표시 반영 → 5절 정비안 → 6절 사이트 → 나머지 `check` 신호 → 7절 확인 → 커밋·푸시. 중간 보고마다 숫자(건수·해석률·후보 수·정밀도)로.

# 하지 않을 것
위법·무효 단정, 지자체·부서·의회 평가나 비교 순위, 담당자 개인정보, 로그인 뒤·비공개 자료, AI 가 쓴 문장을 승인 없이 노출, 부칙·경과조치 자동 작성, 원문에 없는 조문 번호·날짜, 판례·해석례 장문 복사.

# 출력 형식
마크다운. API 실측 표 → 수집 건수 표(지자체별) → 파싱 해석률 → 신호별 후보 수·confidence → 표본 검증 안내 → 변경 파일 목록. 전문 용어는 처음 나올 때 한 줄 풀이(위임 조례, 신구조문대비표, 일괄개정 등).
