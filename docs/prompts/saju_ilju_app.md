## 만들 것
생년월일시·성별·(양력/음력, 출생지 경도)를 넣으면 다음을 보여 주는 단일 페이지 추명 앱 + 서버 API.
1. 명식 4주 표 — 만세력은 간명 앱 `manse.사주(년,월,일,시,분,{성별,출생지,야자시})` 로 세우고 chapgyeong-input.js `fromManse` 로 엔진에 넘긴다. 대운수는 `manse.대운수` (절입까지 날수 ÷3 반올림, 첩경 2권 '2올림 1버림'과 같음)
2. 일주론: 일주(日柱) 60갑자별 해설. 데이터는 data/ilju60.json 에서 읽는다(아래 스키마). 코드에 해설 문장을 박지 않는다.
3. 12운성: 일간 기준으로 연·월·일·시 지지 4곳 + 대운 10개 + 올해 세운의 운성. 첩경식(수토동궁)을 기본으로 하고,
   화토동궁(연해자평식)을 옵션으로 둔다. 어느 식인지 화면에 표기.
4. 12신살: 생년 지지 기준과 일지 기준을 둘 다 계산해 나란히 표시(첩경 53쪽 경험기 — 둘 다 일리 있음).
   기존 길신 19·흉살 20 판정도 함께 표로.
5. 해설 생성: 기존 haeseol 브리프에 위 1~4 재료를 추가하고, LLM(Claude, 서버 환경변수 그대로)이 해설을 쓰되
   checkOutput 에 다음 검사를 더한다 — 일주 해설이 ilju60.json 범위를 벗어난 단정 금지, 운성·신살을 하나도 안 짚으면 위반,
   대운·세운에 대해 '좋다/나쁘다/사고 난다' 같은 시기 길흉 단정 금지(157차 결론). 운은 '글자 변화와 운성 자리'만 서술.
6. 결과를 표·칩으로 보여 주고 PDF 저장 또는 인쇄 CSS.

## data/ilju60.json 스키마
```json
[{ "ganji": "甲子", "ko": "갑자", "summary": "…", "traits": ["…"], "relations": "…", "career": "…", "health": "…",
   "caution": "…", "source": { "title": "책 이름", "page": "쪽" } }]
```
× 60. 내용은 내가 따로 채운다. 너는 스키마·검증기(60개 전부 있는지, source 빠진 항목 경고)·화면만 만들고,
자리표시 문장은 "(출처 입력 대기)" 로 둔다. 네가 아는 일주 해설을 지어 넣지 마라.

## 규칙
- 엔진 모듈(chapgyeong-*.js)은 고치지 않는다. 새 코드는 app-ilju/ (화면) 와 chapgyeong-ilju.js (계산 층) 에만.
  꼭 고쳐야 하면 이유를 README 에 새 차수(159차~)로 적는다.
- 12운성 표는 chapgyeong-vol1-tables.js 포태법 표를 재사용한다. 따로 표를 만들지 않는다. 78차 정정(무:사, 기:오) 유지.
- 신살은 analyzeSinsal 결과를 쓰고, 기준(생년/일지)을 라벨에 적는다.
- 해설 문장은 출처(책·쪽)가 있는 것만. 의료·법률·투자 조언 금지, 사망·사고 단정 금지.
- README_RESTORE.md 에는 작성자 개인 명식·경력이 적혀 있다. 앱·테스트·예시 데이터에 넣지 말고, 예시 명식은 책 실례(docs/)에서 가져온다.
- npm test(회귀 127)가 그대로 통과해야 한다. 새 기능은 test/ilju.js 에 추가(60일주 전부 운성·신살 계산 오류 0건, 두 운성식 결과 대조).
- 외부 의존성 추가 금지. 만세력은 간명 앱 `manse` 모듈을 쓴다. @fullstackfamily/manseryeok 은 새로 부르지 않는다(그 모듈이 절입표로 스스로 참조하는 경우만 남김). 화면은 외부 CDN 없이 단일 HTML.
