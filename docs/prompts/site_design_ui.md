# 다잇다 홈페이지 디자인·UI 개선 프롬프트 (운영자 요청 2026-10-06 — 작성만, 실행 안 함)

> 아래 블록을 그대로 디자인·프런트엔드 작업 세션(Claude Code 등)에 넣는다. 사이트 현황 숫자는 2026-10-06 빌드 기준.

# 역할
너는 공공 데이터 포털을 여러 번 설계한 시니어 프로덕트 디자이너 겸 프런트엔드 리드다. 대구 공무원용 산업·기업 자료 사이트 **다잇다**(daitda.co.kr, Astro 정적 사이트, Tailwind 없음, CSS 변수 기반 `src/styles/tokens.css` + `global.css` 340줄)의 디자인과 UI를 **감사(audit) → 정보구조(IA) 재설계 → 디자인 토큰 v2 → 컴포넌트 명세 → 페이지 템플릿 → 구현 계획** 순서로 제안하라. 결과물은 문서와 와이어프레임(ASCII 또는 SVG)이며, 코드는 토큰·컴포넌트 명세 수준까지만 쓴다.

# 지켜야 할 제약(바꾸지 말 것)
- 공공서비스 톤: 큰 글씨(기본 18px, 최소 14px), 넉넉한 여백, 장식 없음, 그림자 없음, 다크모드 없음. 주색 하나(`--primary #1B4F9B`)만 링크·버튼·강조 숫자에 쓰고, 증감 표시에 빨강·초록을 쓰지 않는다(+주색 / −회색).
- 평가·순위·추천 표현 금지(디자인에서도 '베스트'·'TOP'·별점·랭킹 배지 금지). 특정 기업 부각 금지(전수 원칙).
- 글꼴 Pretendard(로컬 woff2), 모서리 4px, 간격 8px 배수, 터치 타깃 44px, 포커스 링 3px — 이 토큰 체계는 유지하고 **확장**한다.
- 서버·AI 호출 없는 정적 사이트. 프레임워크·CSS 라이브러리 추가 금지. 기존 표 도구(「한글 표 복사」「PDF 내려받기」)와 `table.data-table` 규약은 유지.
- 자동 생성 글의 draft 규칙, 출처·기준일 표기는 디자인이 가려서는 안 된다.

# 현재 상태(감사 출발점)
- 글로벌 내비게이션 10개(현황·탐색·산업별·통계·성장 계산기·기업 사전·상장기업·사업·예산·지원 기업·리포트) + 헤더 돋보기. 390px에서 메뉴가 3줄로 줄바꿈되어 헤더가 뷰포트의 1/4을 차지한다. 햄버거·드로어 없음.
- 첫 화면: 가운데 정렬 히어로(그라데이션 표제 "대구 산업 데이터와 정책을 연결합니다", 인기 검색어 칩 7개, 큰 검색창) → "찾아볼 수 있는 기업 지원 사업 600건" 카운터 → 리포트 회전 카드(6초 자동 넘김) → 산단·기업 현황 → 참여 사업별/산업단지별 → 산업별 현황 → 고용 추이 → 최신 글. 섹션 9개가 같은 시각 무게로 세로 나열된다.
- 목록 페이지(기업 사전 13,850곳): 검색창 1 + 셀렉트 5 + 체크박스 1 + 정렬 셀렉트 1이 한 줄 툴바. 결과는 제목+메타 한 줄의 플랫 리스트, 처음 60곳만 HTML. 적용된 필터 요약·초기화·빈 상태 디자인 없음.
- 데이터 페이지(통계 7주제, 상장기업, 성장 계산기): 넓은 표(열 20개 이상)가 `scroll-x`로 가로 스크롤. 고정 헤더·고정 첫 열 없음. 계산기는 한 페이지에 결과 상자 4개(해설·업종·정책 과제·목표)가 세로로 길게 이어진다.
- 색: 주색 1 + 회색 4단계 + 차트 6색(Okabe–Ito). 상태색(성공·경고·오류·정보) 토큰 없음. 표 머리 바탕 `--surface #f5f6f8`.
- 타이포: 모듈러 스케일 없이 h1 31.5 / h2 24 / h3 20 / 본문 18 / small 16 / tiny 14 / 큰 숫자 42px. 행간 1.7 고정(표·숫자에도).
- 접근성: 랜드마크·aria-current·포커스 링·스킵 링크(확인 필요)·`prefers-reduced-motion`(회전 카드만) 적용. 표 캡션은 `data-title` 속성으로만.
- 반응형: 미디어 쿼리 18개가 컴포넌트마다 따로. 브레이크포인트 체계 없음(600·720·760·1000 혼재). 컨테이너 쿼리 미사용.

# 요구 산출물

## 1. 휴리스틱 감사(Heuristic audit)
Nielsen 10 휴리스틱 + WCAG 2.2 AA 기준으로 페이지 유형별(첫 화면·목록·상세·데이터 표·계산기·글)로 문제를 **심각도(Critical/Major/Minor)** 와 **근거(화면 요소·측정값)** 와 함께 표로. 특히 다음을 반드시 판정하라:
- 내비게이션 **인지 부하**: 10개 1단 메뉴의 정보 냄새(information scent)와 그룹화 가능성(카드 소팅 관점: '자료 보기'·'계산·분석'·'기업 찾기'·'사업·지원').
- 첫 화면의 **시각적 위계(visual hierarchy)** 와 **F/Z 패턴** 적합성, 히어로의 콜투액션이 하나인지, 카운터(600건)가 핵심 가치 제안인지.
- 자동 회전 카드(carousel autoplay)의 WCAG 2.2.2 위반 여부와 대안.
- 표의 **데이터 밀도(density)**, 숫자 정렬(`font-variant-numeric: tabular-nums`, 오른쪽 정렬), 고정 헤더·고정 첫 열, 열 우선순위(progressive disclosure).
- 필터 툴바의 **패싯 내비게이션(faceted navigation)** 패턴 적합성, 적용 필터 칩(applied-filter chips)·결과 수·초기화·빈 상태(empty state)·로딩 상태(skeleton).
- 모바일 헤더 3줄 문제와 **터치 타깃**·thumb zone.
- 색 대비(본문·muted·링크 on surface) 측정값, 링크 밑줄 외 식별 수단, 상태 메시지의 색 의존.

## 2. 정보구조(IA)와 내비게이션
- 사이트맵(현재 → 제안)을 트리로. 1단 메뉴는 **5개 이하**(권장 4: 자료 · 기업 · 사업·지원 · 계산기), 2단은 메가 메뉴 또는 페이지 안 **섹션 탭(StatsNav 식)** 로 흡수.
- 모바일은 **드로어(off-canvas) 또는 하단 탭 바** 중 하나를 고르고 이유를 쓴다. 햄버거를 쓰면 라벨("메뉴")을 함께 둔다.
- 브레드크럼·페이지 헤더(제목·메타 라인·기준일·출처)·'표로 보기/그래프로 보기' 토글의 **표준 페이지 템플릿**을 정의.
- 통합 검색의 **타입어헤드(type-ahead)** 결과 그룹(기업·글·사업), 최근 검색, 결과 없음 안내.

## 3. 디자인 토큰 v2(`tokens.css` 확장안)
- **타이포 스케일**: 모듈러 스케일(1.2 또는 1.25) 기반 7단계(display·h1·h2·h3·body·small·tiny), 용도별 행간(본문 1.7 / 표·숫자 1.4 / 제목 1.3), 측정 폭(measure 60–75자).
- **색**: 시맨틱 토큰 계층(`--color-text-primary`, `--color-bg-subtle`, `--color-border-strong`, `--color-accent`, `--color-status-info/warn/error/success` — 평가 색이 아닌 **시스템 상태**용) + 차트 토큰(순서 고정, Okabe–Ito 유지). 모든 조합의 대비 표.
- **간격·레이아웃**: 8pt 그리드, 섹션 간격 토큰(`--section-gap`), 12칼럼 그리드와 **브레이크포인트 4개**(sm 480 / md 768 / lg 1024 / xl 1280) 또는 컨테이너 쿼리 기준, 컨테이너 폭(글 720 / 표 1080 / 전폭 1280).
- **모션**: duration·easing 토큰 2–3개, `prefers-reduced-motion` 전역 규칙.
- **밀도**: 표의 compact/comfortable 두 밀도 토큰.

## 4. 컴포넌트 명세(상태·변형·접근성 포함)
각 컴포넌트는 해부(anatomy)·변형(variants)·상태(default/hover/focus/active/disabled/loading/empty/error)·반응형 동작·ARIA 패턴·토큰 매핑을 적는다:
- 글로벌 헤더(데스크톱 메가 메뉴 / 모바일 드로어), 스킵 링크, 검색 인풋(type-ahead)
- 페이지 헤더, 브레드크럼, 섹션 헤더(제목+메타+액션)
- **데이터 테이블**: 고정 헤더, 고정 첫 열, 숫자 열 오른쪽 정렬·tabular-nums, 단위 행, 열 숨김(우선순위 속성), 정렬 아이콘, 행 호버, 캡션(`<caption>`), 모바일 카드 전환(responsive table → stacked cards) 규칙, 표 도구 버튼 위치
- 필터 툴바: 패싯 셀렉트/콤보박스, 적용 필터 칩, 결과 수 라이브 리전, 초기화, 빈 상태 일러스트 없이 텍스트 안내
- 카드(리포트·기업·통계 요약), 스탯 타일(큰 숫자+라벨+기준일), KPI 비교 타일(지금/추세/전국)
- 계산기 패널: 입력 그룹(label-input-unit), 스티키 결과 요약, 프리셋 버튼 그룹(세그먼트 컨트롤), 범위·주의 문구의 시각 처리(aside/callout 토큰)
- 콜아웃/노트(출처·주의·예시 배너), 토스트(복사·저장 알림), 로딩 스켈레톤
- 차트 래퍼: 제목·단위·출처·'표로 보기' 토글·범례 위치, 색각 이상 대비 패턴

## 5. 페이지 템플릿 와이어프레임(데스크톱 1280 / 모바일 390)
첫 화면, 목록(기업 사전), 상세(기업·상장기업), 통계 주제, 성장 계산기, 글(리포트) 6종. 첫 화면은 **한 가지 핵심 행동(검색)** 과 **세 가지 진입점(기업 찾기·통계 보기·사업 찾기)** 으로 압축하고, 나머지는 접힌 섹션 또는 2단 그리드로 재배치한다. 자동 회전 카드는 수동 캐러셀 또는 정적 3장 그리드로 바꾼다.

## 6. 구현 계획과 수용 기준
- Astro 컴포넌트 단위 작업 순서(토큰 → 헤더/내비 → 표 → 필터 → 첫 화면 → 계산기), 각 단계의 **회귀 위험**(표 도구, 검색 색인, 인쇄 CSS, PDF 생성)과 검증 방법.
- 수용 기준: Lighthouse 접근성 100·성능 90 이상(모바일), axe 위반 0, CLS < 0.1, LCP < 2.5s(폰트 `font-display: swap`·프리로드), 모든 페이지 390px에서 가로 스크롤은 `scroll-x` 영역 안에서만, 헤더 높이 ≤ 56px(모바일), 대비 AA 전 조합 통과, 키보드만으로 모든 필터·계산기 조작 가능.
- Before/After 스크린샷 체크리스트(PC·모바일 × 6 템플릿)와 측정 스크립트(Playwright) 개요.

# 출력 형식
마크다운. 1절 감사 표 → 2절 IA 트리 → 3절 토큰 표(CSS 변수명·값·용도) → 4절 컴포넌트 명세 → 5절 와이어프레임 → 6절 계획·수용 기준 → 마지막에 '하지 않을 것'(제약 위반 항목) 목록. 전문 용어는 처음 나올 때 한 줄 풀이를 괄호로 붙인다. 디자인 근거는 가능한 한 측정값(대비, 픽셀, 줄 수, 클릭 수)으로 적는다.
