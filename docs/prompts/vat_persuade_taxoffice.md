# 프롬프트 — 가장 적은 노력으로 세무서 담당자를 설득하는 경정청구 꾸러미

> 쓰는 법: 이 파일 전체를 Claude Code 세션에 붙여 넣고 "그대로 실행해"라고 한다.
> 만든 날 2026-11-24. 대상 화면 https://vat-suseong.pages.dev/vat/review/ (같은 코드가 `vat-<지자체>.pages.dev` 모두에 쓰인다)
> 첫 사례 수성구. 운영자가 올린 실제 신고서·e호조 지출 자료는 **세션 scratchpad 에만** 둔다. 저장소에는 코드·규칙·지어낸 고정 자료만 넣는다.

---

## 0. 목표 한 줄

**신규 공무원이 신고서와 매입 목록을 올리고 서명·계좌만 채워 내면, 세무서 담당 조사관이 보정요구 없이 첫 검토에서 인용(일부 인용 포함) 판단을 내릴 수 있는 경정청구 꾸러미를 앱이 만든다.**

'설득'은 말솜씨가 아니라 **조사관이 스스로 확인하려던 것을 먼저 꺼내 놓는 것**이다. 유리한 것만 내지 않는다. 불리한 사실(매출 누락 가능성, 다툼 소지)을 먼저 밝히고, 그 몫을 따로 떼어 처리 방법까지 붙이면 나머지 청구의 신뢰가 올라간다.

## 1. 세 사람의 눈 — 이 셋을 동시에 연기한다

작업마다 세 역할을 번갈아 맡고, 각 역할의 판정을 기록에 남긴다. 한 역할이 '아니오'라고 하면 그 작업은 끝나지 않은 것이다.

| | A. 지자체 부가세를 맡은 세무회계법인 파트너 | B. 관할 세무서 부가가치세과 담당 조사관 | C. 세무를 모르는 신규 공무원 |
|---|---|---|---|
| 경력 | 지자체·공기업 경정청구 대리 다수, 부인·보정 사례를 안다 | 경정청구를 받아 2개월 안에 통지해야 한다(국세기본법 제45조의2 제3항 — 원문 대조) | 발령 3개월, 부가세 신고는 전임자 파일을 따라 했다 |
| 묻는 것 | 이 청구가 부인되거나 매출 쪽 추징을 부르지 않나? 무엇을 나눠 내야 안전한가? | 이 숫자는 어디서 왔나? 실지귀속·과세사업 해당·안분 기준·공급받는자 번호를 내가 다시 확인해야 하나? 이 기관은 그 시설 매출을 신고했나? | 내가 무엇을, 어디서, 몇 번 눌러 하면 되나? 상사에게 뭐라고 보고하나? 틀리면 내 책임인가? |
| 통과 기준 | 쟁점마다 위험 등급과 대응이 있고, 매출 누락 쟁점은 수정신고와 함께 가는 길이 적혀 있다 | 꾸러미만 보고 보정요구서에 적을 항목이 0개(또는 '현장확인으로만 볼 것'만 남음) | 할 일이 7개 이하, 각 할 일에 '어디서·무엇을·누구에게'가 있고, 모르는 낱말이 없다 |

B 역할은 **실제 조사관이 의심하는 순서**로 읽는다: ① 형식(서식·기한·서명·첨부) → ② 숫자 출처(신고서 칸 ↔ 합계표 ↔ 세금계산서) → ③ 과세사업 해당(그 시설에서 과세 매출을 신고했나) → ④ 실지귀속(그 지출이 정말 그 시설 것인가) → ⑤ 안분(기준·면적·정산·재계산) → ⑥ 중복·이미 공제 → ⑦ 받는 쪽 번호·사업장 단위 → ⑧ 매출 쪽 역추징(과소신고·세금계산서 미발급 가산세).

## 3. 바꾸면 안 되는 것

1. 판정 규칙·계산은 조문·유권해석 원문을 대조한 근거가 있을 때만 바꾼다. 근거 없는 '설득용' 해석을 넣지 않는다.
2. 기관 신고 금액·내부 문서·개인정보(대표자·주민번호·계좌·전화·이메일·담당자 이름)는 저장소·화면 예시·커밋 메시지·CLAUDE.md 에 넣지 않는다. 실제 자료 결과는 scratchpad 에만.
3. 평가·절세·'반드시 환급' 같은 문구 금지. 결과 화면 머리의 '판정은 참고이며 기관의 판단이 아닙니다'를 유지한다.
4. 세무서를 압박하거나 기한·불복을 위협처럼 쓰는 문장 금지. 불복 절차는 사실 안내 한 줄로만.
5. 다잇다 사이트와 점검기 사이트는 서로 링크하지 않는다.
6. 커밋과 푸시는 따로(코드만). PR 을 만들지 않는다.

## 4. 단계

### 1단계 — 조사관의 질문 은행 (B 중심, A 가 보탬)

1. 2절의 작업서 「세무서가 볼 것」 11단계와 「법령 검토」 16쟁점을 B 의 ①~⑧ 순서로 다시 묶어 **질문 은행**을 만든다. 질문마다:
   `번호 · 조사관이 묻는 말(그의 말투로) · 왜 묻나(조문) · 무엇을 보면 끝나나(증빙 한 가지) · 앱이 이미 가진 값 · 공무원이 구해야 할 것 · 못 구하면 어떻게(청구에서 떼기 / 사전 질의 / 현장확인 요청)`
2. A 역할로 **보정요구·부인 사례**를 덧붙인다. 출처가 있는 것만(국세법령정보시스템 질의회신·심판례, 감사 지적 `cases.yml`, 권익위). 없으면 '실무 경험상'이라 쓰지 말고 빼라.
3. 국세기본법 제45조의2·시행령 제25조의3(청구서 기재·증명서류) 현행 원문을 받아 대조한다(`data/guidelines/national-tax-basic` 저장본 또는 `LSW/lsInfoR.do`). 2개월 통지·보정 요구·기간 계산을 원문 문장으로 적는다.
4. 결과: `docs/design/vat-persuade-questions.md`(질문 은행, 30개 안팎). 수성구 숫자 없이.

### 2단계 — 쟁점 위험 등급과 '나눠 내기' 전략 (A 중심)

꾸러미의 금액을 쟁점 단위로 나누고 등급을 매긴다. 등급은 판정이 아니라 **제출 방법**을 정하는 꼬리표다.

| 등급 | 뜻 | 예 | 제출 방법 |
|---|---|---|---|
| 1 계산 정정 | 신고서·합계표 숫자만으로 다시 계산된다 | 안분 식 오류, 정산 누락, 신고서 칸 합 불일치 | 바로 청구. 증빙 = 신고서·명세서 사본 |
| 2 증빙으로 끝남 | 사실 하나(계약서·면적표·조례 요금표)를 붙이면 끝 | 과세 시설 공사비 미공제, 신고에 빠진 세금계산서(받는 쪽 번호가 우리 번호) | 증빙을 붙여 청구 |
| 3 매출과 함께 | 공제하려면 그 시설 과세 매출 신고가 전제 | 신고서 과세표준 명세에 그 업종 매출이 없는 시설(salesGap) | **수정신고(매출) + 경정청구(매입)를 같이** 내는 안과 그 몫을 떼어 두는 안을 나란히, 순액(가산세 포함)으로 비교 |
| 4 해석 다툼 | 유권해석이 갈리거나 사실 판단이 필요 | 관람석 경기장 해당 여부, 복합 건물 과세 몫, 본청 공통 안분 기준 | 청구에서 떼어 **세법해석 사전답변·서면질의 초안**(rules.yml inquiries)으로. 또는 다툼 몫만 별도 청구 |

- 신고서 한 장(과세기간·예정/확정)마다 등급별 금액을 보이고, **'먼저 낼 묶음'(1·2등급)**과 '나중 묶음'을 자동으로 가른다. 경정청구 기한이 가까운 기간(D-90 안)은 3·4등급이라도 기한 보전용으로 먼저 내는 안을 적는다(근거: 기한이 지나면 청구 불가 — 국세기본법 제45조의2 제1항).
- 3등급은 가산세 어림(`penaltyCalc`, 과소신고·납부지연, 세금계산서 미발급 법 제60조 제2항 제2호)과 수정신고 감면(국세기본법 제48조 제2항)을 붙여 **함께 냈을 때 순으로 남는 돈**을 보여 준다. 남는 돈이 음수면 청구하지 말라는 것이 아니라 그 사실을 적는다.

### 3단계 — 조사관이 한 쪽에서 판단하게: '검토 요약서' (B 중심)

경정청구서·사유서 앞에 붙일 **검토 요약서 1쪽**(A4, PDF + 엑셀 첫 시트 같은 내용)을 만든다. 조사관이 읽는 순서대로:

1. 청구 요지 한 문장(기관·과세기간 수·돌려받을 세액·등급 1·2 합계)
2. 과세기간 표: 기간 · 신고 구분 · 당초 (16)(17)(18) → 경정 후 · 차액 · 등급 · 증빙 번호
3. 쟁점 3개까지(금액 큰 순): 사실 한 줄 · 근거 조문/유권해석 번호 · 붙임 번호
4. **기관이 먼저 밝히는 것**: 3·4등급 몫과 처리(수정신고 동시 제출 / 사전답변 신청 / 이번 청구에서 뺌)
5. 붙임 목록(번호 = 파일 이름 앞 번호)
6. 문의: 부서 이름만(사람 이름·전화는 공무원이 손으로 적는 빈칸)

조건: 쉬운 말이 아니라 **세무서 용어**(공급가액·매입세액·불공제·실지귀속·안분·정산)로 쓴다 — 신규 공무원용 풀이는 다른 파일(5단계)로 가른다. 금액은 원 단위, 출처 칸을 단다. 평가 낱말 없음.

### 4단계 — 증빙을 공무원이 모으지 않게 (C 중심, A 가 점검)

1. 질문 은행의 '공무원이 구해야 할 것'을 증빙 목록으로 묶어, **앱이 만들 수 있는 것**과 **사람이 가져와야 하는 것**으로 가른다.
   - 앱이 만든다: 신고서별 재계산표, 매입처별 세금계산서합계표 추가분 밑자료(공급자별), 건별 귀속 명세(세금계산서 ↔ 시설 ↔ 계약), 조례 요금표 발췌(과세 매출 근거 — 자치법규 원문 조문 번호와 링크), 나라장터 계약 목록, 법령·유권해석 원문 발췌(rules.yml rulings 의 text), 면세비율 계산표
   - 사람이 가져온다: 계약서·준공검사 조서, 시설 면적표(건축물대장 — 공개라면 앱이 주소를 적어 준다), 세입 실적(e호조), 사업장 등록 현황
2. 사람이 가져올 것은 **부서별 요청 메모**(받는 부서·필요한 서류·왜·어느 과세기간·마감)로 자동 생성한다 — 공무원은 내부 메신저에 붙여넣기만.
3. 건축물대장·조례처럼 공개 자료로 대신할 수 있는 증빙은 대신한다. 못 대신하면 그 쟁점을 2→4등급으로 내리지 말고 '증빙 대기'로 표시한다.

### 5단계 — 신규 공무원 할 일 7개 이하 (C 중심)

꾸러미 안 `0_이렇게_하세요.txt`(및 결과 화면 한 줄)를 **체크리스트 7개 이하**로 다시 쓴다. 각 줄: `무엇을 · 어디서(메뉴 경로) · 걸리는 시간 어림 · 끝났는지 아는 법`.
예시 틀(실제 문장은 C 역할 시험으로 다듬는다):
1. 묶음의 경정청구서 PDF 에 기관장 성명·서명, 환급 계좌, 청구 날짜를 적는다
2. 부서별 요청 메모를 각 부서에 보낸다(증빙 대기 쟁점이 있을 때만)
3. 결재를 받는다 — 결재용 한 쪽은 '검토 요약서'를 그대로 쓴다
4. 관할 세무서 부가가치세과에 **사전 상담 전화**를 한다 — 아래 대본으로
5. 홈택스 경정청구 메뉴에 칸 값을 옮기고 붙임을 올린다(칸 번호 ↔ 묶음 표)
6. 보정요구가 오면 `보정_답변_틀` 에서 그 질문 번호를 찾아 붙임과 함께 회신한다
7. 환급되면 세외수입으로 처리한다(국고보조금 통합관리지침 제26조 제2항·지방보조금 관리기준 — 원문 대조, cases.yml 합동감사 지적)

함께 만들 것:
- **세무서 사전 상담 대본**(3분 분량): 인사 → 청구 요지 한 문장 → "먼저 밝혀 둘 것"(3·4등급) → 조사관이 물을 법한 질문 5개와 답(질문 은행에서 금액 큰 쟁점 순) → 받을 답(보완 서류·제출 방식·현장확인 여부)을 적을 빈칸
- **보정요구 답변 틀**: 질문 은행 번호별 답변 문장 + 붙임 번호. 조사관 질문 문장을 붙여 넣으면 가장 가까운 번호를 찾아 주는 것은 하지 않는다(규칙 매칭이 틀리면 더 큰 일) — 번호 목록만.
- 상사 보고용 세 줄(무엇을·얼마·위험): 검토 요약서 1번과 4번에서 자동.

### 6단계 — 구현

- 새 파일보다 기존 함수 확장 우선: 등급·질문 번호는 `vat_diag.ts` 진단 항목과 `vat_casebook.ts` 시트에, 검토 요약서는 `vat_claimform.ts` 옆 `summaryDocPdf`(같은 `pdfKit`), 묶음 구성은 `vat_review.ts caseFiles`.
- 질문 은행·등급 기준·대본·보정 답변 틀의 문장은 코드가 아니라 `data/vat/rules.yml` 새 칸(`persuade:` — `questions[]`, `grades[]`, `script`, `requests`)에 두고 조문 링크를 단다. 문장 속 숫자는 화면이 채운다.
- 결과 화면은 단추를 늘리지 않는다. 지금의 강조 내려받기 하나(`#rf-dl-submit`)가 새 묶음(아래 순서)을 주게 하고, 다른 형식은 접힘 안.
- 묶음 파일 순서(앞 번호 = 붙임 번호):

### 7단계 — 세 역할 시험 (이 단계가 '설득'의 검증이다)

1. **B 시험(조사관)**: 하위 에이전트에게 B 역할과 1절 ①~⑧ 순서, 국세기본법 제45조의2 원문만 주고 **묶음 파일만** 읽혀 보정요구서를 쓰게 한다. 질문 은행·앱 설명은 주지 않는다(답을 미리 알면 시험이 아니다). 나온 보정 항목마다 꾸러미를 고치고 다시 돌린다 — 보정 항목이 0이거나 '현장확인으로만 볼 것'만 남을 때까지, 최대 3회. 각 회의 보정 항목 수를 기록한다.
2. **A 시험(세무법인)**: 다른 하위 에이전트에게 A 역할로 같은 묶음을 주고 '부인·추징 위험 순위 5개와 고칠 점'을 받는다. 근거 없는 지적은 버리고, 조문이 있는 지적만 반영한다.
3. **C 시험(신규 공무원)**: Playwright 로 결과 화면 → 내려받기 → `00_이렇게_하세요` 까지의 클릭·입력 수를 재고, 하위 에이전트에게 C 역할로 `00` 파일과 검토 요약서만 주어 '모르는 낱말·막히는 줄'을 받는다. 할 일 7개 이하, 막히는 줄 0을 기준으로.
4. 고정 자료로 1~3을 먼저 돌리고, 통과하면 scratchpad 의 수성구 실제 자료로 한 번 더 돌린다. 실제 자료 결과(보정 항목·금액)는 scratchpad 에만 남기고 운영자에게 파일로 보낸다.
5. `scripts/vat_ux_test.mjs` 에 P1~P6(등급 분류·검토 요약서 존재·묶음 파일 순서·3등급 비교표·요청 메모·할 일 7개 이하)을 더하고 전체가 통과해야 한다.

### 8단계 — 기록·배포·보고

- `docs/design/vat-persuade.md`: 질문 은행 요약, 등급 기준, 세 역할 시험의 회차별 결과(고정 자료 기준 숫자만), 남은 것.

- 빌드(`VAT_SITE=1`, 동시에 두 번 돌리지 않음) → 시험 → 커밋(코드만) → 푸시(따로) → 배포 확인.

## 5. 판단이 갈릴 때

- 돌려받을 금액을 키우는 것과 조사관이 받아들이는 것이 부딪치면 **받아들이는 쪽**을 고른다. 떼어 낸 몫은 사라지는 게 아니라 '나중 묶음'으로 남긴다.
- 근거가 2차 전재뿐인 유권해석은 검토 요약서에 넣지 말고 사유서 각주로만, '원문 확인 필요'를 단다.
- 조사관 시험 에이전트가 법령 밖의 요구(관행)를 하면 기록만 하고 꾸러미를 바꾸지 않는다 — 단, 증빙 하나로 끝나는 요구라면 붙인다(공무원 노력이 늘지 않을 때만).
