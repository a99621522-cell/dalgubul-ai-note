# 지난 부가세 돌려받기 — 3차 UX 프롬프트: "올리고, 확인하고, 받는다"

> 이 프롬프트를 그대로 실행한다. 대상 화면은 지자체 전용 사이트의 `/vat/review/`(예: https://vat-suseong.pages.dev/vat/review/) 하나다.
> 계산·판정 규칙(`data/vat/rules.yml`, `vat_rules.ts judge`, `vat_casebook.ts`, `vat_diag.ts`)은 한 줄도 바꾸지 않는다. 화면·흐름·파일만 바꾼다.

## 0. 역할

너는 공공기관 업무 도구를 10년 넘게 설계해 온 UI/UX 책임자다. 사용자 조사 → 측정 → 설계 → 구현 → 수용 시험까지 직접 한다.
"기능을 더하는 것"이 아니라 **담당자가 할 일을 줄이는 것**으로 평가받는다.

## 1. 사용자(실제 관찰에서 나온 사실 — 지어내지 않는다)

- 구청 세무 담당 공무원 1명. 부가가치세 경정청구를 처음 맡았다. 크롬이 아니라 **엣지**, 1920×1080 모니터, 기관 PC.
- 가진 자료는 **세 가지뿐**이다.
  1. 홈택스에서 받은 지난 부가가치세 신고서 PDF(5년치, 예정·확정 약 20장)
  2. e호조 「채권자별 내역조회(매입 전자세금계산서)」 엑셀(5년치 약 2만~3만 건) — **기관 문서보안(DRM)으로 암호화된 .pLDH 파일**이라 파일로는 못 연다. 그 PC 의 엑셀에서는 열린다
  3. 구가 확인해 준 사실(면적 비율·운영 방식 등)을 적은 한글 설명자료 — 운영자가 예시 설정에 넣는다(담당자가 올리는 파일이 아님)
- 홈택스 매입 세금계산서 목록은 **받지 않는다**(3개월·1,000건씩이라 5년이면 수백 번, 건마다 어느 사업인지 알 수 없음).
- 담당자가 실제로 겪은 일(2026-11-24~25):
  - 신고서 PDF 를 올렸는데 "스캔한 PDF 는 읽지 못한다"는 엉뚱한 안내를 받았다
  - 암호화된 엑셀을 올릴 방법을 몰랐다
  - 다음 날 다시 열었더니 올린 자료가 사라져 신고서를 다시 올려야 했다(저장 한도 초과)
  - 운영자가 설정을 고쳤는데 담당자 화면은 예전 설정 그대로였다(「처음부터 다시」를 몰랐다)
  - 결과 화면이 길고 복잡하다 — "사이트에 만들면 복잡해, 엑셀로", "고친 신고서는 국세청 양식으로 PDF 와 고칠 수 있는 문서로"
- 담당자가 원하는 최종물: **과세기간마다 고친 신고서(국세청 서식) + 이유 + 근거 법령·규정 + 근거 자료**, 파일로.

## 2. 목표(측정 가능한 것만)

| 지표 | 지금(측정해서 채움) | 목표 |
|---|---|---|
| 처음 연 뒤 첫 파일(고친 신고서)을 받기까지 담당자 행동 수(클릭·붙여넣기·선택) | | 6 이하 |
| 그 사이 담당자가 읽어야 하는 화면 글자 수 | | 지금의 1/3 |
| 시설을 직접 정해야 하는 세부사업 수(5년치 실자료) | | 30 이하(나머지는 기본값, 바꾸기 가능) |
| 다시 열었을 때 다시 올려야 하는 파일 | | 0 |
| 운영자가 설정을 바꾼 뒤 담당자가 할 일 | | 0 |
| 첫 화면에 보이는 단추 | | 강조 단추 1개 |
| 2만 건 붙여넣기 뒤 결과까지 화면이 '멈춘 듯' 보이는 시간 | | 0(진행 표시) |

## 3. 원칙

1. **세 걸음만 보인다** — ① 자료 넣기 ② 확인할 것(필요할 때만) ③ 받기. 나머지(진단 표·공급자 표·사례·가산세·근거 원문)는 화면에서 치우고 받는 파일 안으로 옮긴다.
2. **화면은 요약, 내용은 파일** — 결과 화면은 "얼마를, 몇 개 과세기간에서" 한 문장과 받기 단추. 이유·근거·고친 값은 엑셀·PDF·Word 에.
3. **기본값으로 끝까지 간다** — 모르는 사실은 돌려받을 돈을 적게 잡는 쪽 기본값으로 계산하고, 답하면 늘어나는 것만 "확인할 것"으로 묻는다(질문은 걸린 금액 큰 순 5개까지).
4. **한 번 넣은 것은 다시 넣지 않는다** — 자료·결정은 브라우저에 남고(IndexedDB), 설정 갱신은 저절로 반영된다.
5. **잠긴 파일·못 읽는 파일은 그 자리에서 해결법을 말한다** — "왜 못 읽었나"와 "지금 할 일 한 가지".
6. **말은 담당자 말로** — 화면에 서식 칸 번호·세법 용어를 쓰지 않는다(파일에는 쓴다). 숫자는 원 단위 쉼표.
7. 판정은 참고이며 기관의 판단이 아니다 — 결과 문장 바로 아래 한 줄. 돌려받는 쪽으로만(더 낼 수 있는 몫은 청구에서 빼고 따로 알림). 개인정보(대표자 주민번호·계좌·전화)는 읽지도 쓰지도 않는다. 서버·AI 호출 없음.

## 4. 할 일(순서대로)

### 4-1. 관찰·측정(코드 고치기 전)
- 지어낸 값으로 실제 규모를 흉내 낸 고정 자료를 만든다: 신고서 20장(예정·확정, 과세표준 명세·불공제 명세 포함), e호조 지출 3만 건(세부사업 1,000개, 부가세 0 건 20% 포함). 실제 기관 파일·금액은 저장소에 넣지 않는다.
- Playwright 로 엣지와 같은 크로미움, 1920×1080·1366×768 에서 "처음 열기 → 첫 파일 받기"를 돌려 2절 표의 '지금' 칸을 잰다. 행동마다 화면 그림을 남긴다.
- 담당자 관점 think-aloud 대본(과업 5개: 자료 넣기 / 잠긴 엑셀 넣기 / 다음 날 다시 열기 / 확인할 것 답하기 / 고친 신고서 받기)으로 막히는 지점을 적는다.
- 결과: `docs/design/vat-review-ux3-audit.md`(막힌 곳 목록, 원인, 심각도 1~3).

### 4-2. 설계
- 한 화면 와이어프레임(텍스트로): 머리(기관·저장됨) → ① 자료 넣기 상자 하나(파일 끌어다 놓기 + "엑셀에서 복사해 Ctrl+V" + 읽은 결과를 한 줄씩: "신고서 20장 — 2021년 제2기 ~ 2026년 제2기", "지출 27,081건(e호조)") → ② 확인할 것(0~5개, 각 질문은 버튼 2~3개, 답하면 바로 금액 갱신) → ③ "○○구는 N원을 돌려받을 수 있습니다(과세기간 M개)" + 강조 단추 「고친 신고서 받기」 하나 + 작은 글 "PDF만 · Word만 · 엑셀만".
- 「고친 신고서 받기」 = zip 하나: `1_고친신고서_국세청서식.pdf`, `2_고친신고서_고칠수있는문서.docx`, `3_과세기간별_이유_근거.xlsx`(과세기간마다 시트: 고친 값·이유·근거 법령·근거 자료·건별 목록), `0_이렇게_하세요.txt`(홈택스 메뉴 경로·순서 7줄 이내). 세무서 내부용(대본·답변틀·작업서)은 `참고/` 폴더.
- 세부사업 정하기: 세액 큰 순 30개만 "이 사업은 어느 시설?" 카드(시설 짐작이 있으면 미리 골라 둠, 「맞음」 한 번), 나머지는 기본값(면세·행정 — 셈에서 뺌)으로 두고 "더 정하기"로만 연다.
- 진행 표시: 신고서 읽기·붙여넣기 처리 중에 "20장 중 7장 읽는 중", "27,081건 정리 중"을 보이고 끝나면 ③으로 스크롤.
- 결과: `docs/design/vat-review-ux3-spec.md`(와이어프레임, 문구표, 상태별 화면: 처음/자료 넣는 중/확인할 것 있음/끝, 수용 기준).

### 4-3. 구현(작은 커밋 5개 이하)
- 화면에서 치운 표·절은 지우지 말고 파일 쪽으로 옮기거나 「자세히」 하나에 모은다(기존 수용 시험이 쓰는 id 는 유지하거나 시험을 같이 고친다).
- 계산은 기존 함수(`refundCalc`, `caseCorrDocs`, `caseBook`, `claimFormPdf`, `claimFormDocx`, `persuadeFiles`)를 그대로 부른다.
- 지자체 전용 사이트(`VAT_GOV`)에서만 다른 문구가 필요하면 `data/vat/govs.yml` 로, 코드에 지자체 이름을 쓰지 않는다.

### 4-4. 시험·측정·보고
- `scripts/vat_ux_test.mjs` 에 과업 5개 시나리오(R3-1~R3-5)를 더하고, 2절 표의 '목표'를 수용 기준으로 단언한다. 기존 시험은 모두 통과해야 한다. 전용 사이트 시험(`scripts/vat_gov_site_test.mjs`)도.
- 2절 표의 '지금'과 '고친 뒤'를 `docs/design/vat-review-ux3-after.tsv` 로.
- CLAUDE.md 에 한 문단(기관 금액·이름 없이).
- 운영자에게: 바뀐 흐름 화면 그림 3장(처음·확인할 것·끝), 받는 zip 견본(지어낸 값), 사용 설명서(HWPX) 갱신본.

## 5. 하지 않는 것

- 판정 규칙·계산식 바꾸기, 새 세법 해석 넣기
- 결과 화면에 표를 더 넣기(표는 파일로)
- 담당자에게 홈택스 매입 목록을 받으라고 하기
- 실제 기관 파일·금액·사람 이름을 저장소·시험 자료에 넣기
- 평가·절세 권유 문구
