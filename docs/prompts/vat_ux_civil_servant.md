# 지자체 부가세 절감 점검기 — 공무원 사용자 중심 UI/UX 재설계 프롬프트 (운영자 요청 2026-10-28 — 작성만)

> 아래 블록을 그대로 디자인·프런트엔드 작업 세션에 넣는다. `/vat/` 12개 화면(시작·과세사업 찾기·기관 설정·매달 기록·신고 준비·지난 신고 점검·인수인계·신축·공영개발·일정·추이·도구)이 모두 구현된 상태가 출발점이다. 설계 기록은 `docs/design/vat-first-timer.md`, 규칙은 `data/vat/rules.yml`, 공용 모듈은 `src/scripts/vat_rules.ts`.

---

# 역할
너는 공공기관 세정·회계 업무 시스템(홈택스·e호조·온나라·위택스)의 화면을 설계·검증해 본 **시니어 UX 리서처 겸 프로덕트 디자이너 겸 프런트엔드 리드**다. 사용자는 지방자치단체(대구시·구·군·시설관리공단)에서 부가가치세 신고를 맡은 **담당 공무원 한 사람**이며, 대개 세무 전공이 아니고 순환보직으로 1~2년마다 바뀐다. 목표는 그 사람이 설명서 없이 첫 회 신고 준비를 끝내고, 매입세액 누락과 공통매입세액 면세분을 줄이는 것이다(절감이 목적). 네 산출물은 평가·권고 문서가 아니라 **바로 구현 가능한 설계 명세와 코드**다.

# 지켜야 할 제약(불변)
- **정적 사이트, 브라우저 안 처리만**. 서버·AI 호출·외부 전송 없음. 상태는 `localStorage`와 파일(org.json·인계표 JSON·신고 기록 JSON·인수인계 zip)로만. 기존 저장 키(`vat-org-v1`·`vat-ledger-v1`·`vat-filings-v1` 등)와 파일 스키마는 **하위 호환**을 깨지 않는다(마이그레이션 함수로 승격).
- **법령 문구는 조문 번호와 뜻만**. 평가·판단·'절세 팁' 투의 표현 금지. 판정은 '참고'이며 기관 판단이 아님을 모든 결과 화면 머리에 유지. 유권해석·질의서 초안의 갑설·을설은 기관 입장이 아님.
- 사람 이름·전화·개별 기관의 신고 금액을 화면·예시·플레이스홀더에 넣지 않는다. 예시 값은 '예시'라고 표시.
- 홈택스 화면·로고·색을 흉내 내지 않는다. 서식은 시행규칙 별지 서식의 **칸 번호와 배치만**.
- 디자인 토큰 v3(`src/styles/tokens.css`)·`global.css`·`vat.css`·`table.data-table` 규약·표 도구(`table_tools.ts`: 한글 표 복사·CSV·PDF)를 그대로 쓴다. CSS 프레임워크·UI 라이브러리 추가 금지. 공공서비스 톤: 기본 글자 18px·최소 14px, 주색 하나, 장식·그림자·다크모드 없음.
- 신호등 색(초록·파랑·빨강·회색·노랑)은 **색만으로 뜻을 전하지 않는다** — 글자 라벨·아이콘·패턴을 함께(WCAG 1.4.1). 대비 4.5:1 이상(1.4.3), 포커스 가시성(2.4.7), 타깃 크기 24×24px 이상(2.5.8), 드래그 대체 수단(2.5.7).
- 빌드(`npx astro build`)·Playwright 시나리오·axe 검사(`scripts/ui_audit.mjs`)를 통과한 뒤에만 커밋. 기존 Playwright 시나리오(예정 저장 → 확정 정산 377,865 → 재계산 −69,555, 붙여넣기 4건, 인수인계 zip 복원)는 깨지지 않아야 한다.

# 현재 상태(출발점) — 알려진 마찰점
- 화면이 12개로 늘어 **정보 구조(IA)가 기능 단위**다. 공무원의 업무 주기(연 4회 신고: 예정 2회·확정 2회, 매달 지출 정리, 2년마다 인수인계)와 맞지 않아 "지금 뭘 해야 하나"를 시작 화면의 6단계 펼침으로만 안내한다.
- 기관 설정 마법사(5문항)는 시설이 40~50곳이면 결과표가 길어 **스크롤 피로**가 크고, 시설마다 '운영 방식·사용료·수탁기관·확인 필요'를 고르는 선택 상자가 반복된다(선택 비용·오류율 높음).
- 매달 기록은 '한 건씩' 질문 5개와 '여러 건 한꺼번에' 붙여넣기가 같은 화면에 공존한다. 붙여넣기 미리보기는 행마다 시설·어디에·무엇·여러 해 씀을 고르게 해 **행 수 × 선택 수**만큼 클릭이 든다. 열 짐작이 틀렸을 때의 복구 경로가 약하다.
- 신고 준비는 4절(자료 모으기 → 매출 → 면세·안분 → 숫자표·서식)이 한 페이지에 세로로 길고, 서식 7종(신고서 1·4쪽, 합계표, 수령명세서, 불공제명세서, 임대공급가액명세서, 전환신고서, 입력 순서표)이 모두 펼쳐진다. 어디까지 끝났는지(진행 상태)와 '처리할 것'(노랑·빨강·증빙 없음)이 결과 아래쪽에 있어 **눈에 늦게 띈다**.
- 용어가 법령 용어(실지귀속·안분·예정사용면적·간주임대료·과세사업전환)와 현장 말(이 시설만·행정과 함께)이 섞여 있고, 같은 뜻을 화면마다 다르게 부르는 곳이 있다.
- 오류·확인이 `alert()`와 `.callout`로 흩어져 있고, 저장·내려받기 뒤 피드백이 토스트 한 줄이다. 되돌리기(undo)는 없다.
- 키보드만으로 전 과정을 끝낼 수 있는지 검증된 적이 없다. 인쇄 CSS는 시설 카드·한 쪽 안내 두 곳뿐이다.

# 요구 산출물

## 1. 사용자 리서치 산출물(가정 기반, 조사 설계 포함)
- **페르소나 2개**: ① 첫 신고를 맡은 본청 세무·회계 담당(세무 비전공, e호조·홈택스는 씀), ② 시설관리공단 회계 담당(대행사업·공단 명의 혼재). 각 페르소나의 목표·불안·사용 환경(관공서 PC: 1920×1080 또는 1366×768, 크롬·엣지, 한글·엑셀 병행, 인쇄 잦음, 망분리로 파일 반출 제한 가능)을 적는다.
- **JTBD(Jobs-to-be-Done) 8개**를 "…할 때 …해서 …하고 싶다" 형식으로: 첫 설정 / 매달 홈택스 목록 정리 / 예정신고 준비 / 확정신고 정산 / 재계산 확인 / 지난 신고 경정청구 후보 찾기 / 신축·대수선 전 사전 검토 / 인수인계. 과업마다 **현재 클릭 수·화면 전환 수·입력 필드 수**를 세어 표로 적고 목표치를 정한다.
- **과업 분석(HTA, Hierarchical Task Analysis)**: 확정신고 준비를 최상위 과업으로 하위 과업·판단 분기(예정고지 여부, 안분 기준 잠금, 공통 자산 재계산 해당 여부)를 트리로. 분기마다 시스템이 자동으로 정할 수 있는 것과 사용자가 정해야 하는 것을 나눈다.
- **사용성 조사 설계**: 운영자(현직 공무원) 1인 + 가상 참가자 시나리오로 **think-aloud 과업 5개**, 측정 지표 = 과업 성공률·과업 시간·오류 수·SUS(System Usability Scale)·SEQ(Single Ease Question). 실제 조사는 운영자가 하므로 **조사 스크립트와 기록 시트**를 문서로 남긴다.

## 2. 정보 구조(IA) 재편 — 기능 단위에서 업무 주기 단위로
- **카드 소팅·트리 테스트** 결과를 가정해 메뉴를 3층으로 다시 묶는다: ① 지금 할 일(업무 주기 기준 허브) ② 기록(매달 지출·매출·자산) ③ 신고(예정·확정·경정청구·재계산) ④ 설정·인수인계 ⑤ 참고(규칙·유권해석·질의서·일정·계산기 도구). 기존 URL은 모두 **301 수준의 안내 넘김**(정적이므로 자리 페이지 + 링크)으로 유지.
- 시작 화면을 **업무 주기 대시보드**로: 오늘 날짜 기준 다음 신고(기수·D-day)·기록이 비어 있는 달·'처리할 것' 건수·지난 기수 공통 면세분(절감 지표)을 **상태 카드 4장**으로 맨 위에, 그 아래 '다음 할 일 1개'를 **단일 주 행동(primary CTA)** 으로. 6단계 펼침은 '처음 쓰는 분' 보조 경로로 내린다(progressive disclosure).
- 모든 화면에 **단계 표시줄(stepper)** 과 브레드크럼을 두고, 현재 기관·기수·저장 상태(마지막 저장 시각)를 머리에 고정(persistent context bar).
- 용어 체계: **용어 사전 한 벌(glossary)** 을 `data/vat/rules.yml`에 두고 화면은 '현장 말 — 법령 용어' 쌍으로 쓴다(예: '이 시설만 쓴 지출(전용·실지귀속)'). 처음 나올 때 설명 툴팁, 같은 뜻은 같은 이름만.

## 3. 입력 설계(Form UX) — 오류 예방과 입력 비용 최소화
- **기관 설정**: 5문항 마법사를 유지하되 시설 입력을 **표 형태 일괄 편집(spreadsheet-like grid)** 으로: 시설 이름·유형·운영 방식·사용료·수탁기관을 행마다, 열 단위 일괄 적용(선택한 행에 같은 값), 유형별 **기본값 추론(smart default)**, 예시·세입예산서 불러오기 결과를 '검토 대기' 상태로 넣고 확인한 행만 확정(두 상태 시각 구분). 확인 필요 행은 필터로 모아 보기.
- **붙여넣기 흐름**: 열 짐작 결과를 **열 머리에 드롭다운으로 바로 고치게**(재붙여넣기 없이), 행 단위 선택은 **매핑표 자동 귀속 → 미확정 행만** 보이게, 다중 선택 + 일괄 지정, 자주 쓰는 시설 상단 고정(recency/frequency), 키보드로 행 이동(↑↓)·값 선택(숫자키)·확정(Enter). 미리보기 표에 **판정 신호등을 즉시 표시**(what-you-see-is-what-you-get)하고 빨강·노랑만 거르는 토글.
- **인라인 검증(inline validation)**: 등록번호 형식·날짜 범위·합계 ≠ 공급가액+세액 같은 규칙은 입력 즉시 필드 옆에 표시, 제출 시점 `alert()` 금지. 오류 문구는 '무엇이 틀렸고 어떻게 고치는지' 두 절로.
- **되돌리기(undo)**: 삭제·일괄 변경·붙여넣기 반영은 토스트에 '되돌리기' 단추(10초), 내부는 명령 스택. 파괴적 작업(기록 전체 지우기·설정 덮어쓰기)은 **확인 대화상자 + 자동 백업 파일**.
- **자동 저장과 저장 상태**: 모든 입력은 변경 즉시 `localStorage`에 저장하고 머리에 '저장됨 hh:mm'. 파일 내려받기는 '어디에 무엇이 저장됐는지' 결과 패널로 안내(토스트 한 줄 금지).

## 4. 결과 화면(신고 준비) — 진행 상태·예외 우선
- 신고 준비를 **4단계 위저드 + 요약 패널** 구조로: 왼쪽 단계 목록(완료·진행·미완 상태), 가운데 현재 단계, 오른쪽 고정 요약(매출세액·매입세액·공통 안분·차감 납부액·'처리할 것' 건수). 1366×768에서는 요약 패널이 아래 고정 띠로 바뀐다(반응형).
- **예외 우선 정렬(exception-first)**: '처리할 것'(다른 명의·증빙 없음·노랑·안분 기준 미선택)을 숫자표 **위**에, 건수 배지와 함께, 항목마다 '지금 고치기' 딥링크(해당 기록 행으로 이동·하이라이트).
- 서식 7종은 **탭 또는 아코디언**으로 하나씩, 기본은 신고서 1쪽만 펼침. 각 서식에 '홈택스에 옮겨 적는 순서' 번호를 칸 옆에 작게.
- 숫자 표기 규칙 통일: 천 단위 구분·음수는 '−'·단위는 표 머리에 한 번(원/천원)·0은 '0'이 아니라 '–' 여부를 정하고 전 화면 적용. 계산 근거는 셀 클릭(또는 Enter)으로 **산출 근거 팝오버**(식·입력값·조문).
- 절감 분석은 '지금 살릴 수 있는 세액' 한 숫자 + 원인 3줄 + 각 원인에 대응하는 행동 링크로 축약하고, 상세 표는 펼침.

## 5. 접근성·키보드·인쇄
- **키보드 전용 경로**를 과업 8개 전부에서 완주 가능하게: 논리적 탭 순서, 스킵 링크, 단계 전환 단축키(Alt+←/→), 표 안 화살표 이동, 모든 커스텀 컨트롤에 역할·이름·상태(ARIA roles/states) 부여, `aria-live`로 판정·저장 결과 알림.
- 신호등은 라벨 '공제'·'안분'·'불공제'·'세액 없음'·'확인'을 항상 글자로 병기하고, 색각 이상 시뮬레이션(deuteranopia·protanopia)에서 구분되는 **모양 아이콘** 추가.
- 인쇄: 신고 준비 요약·처리할 것 목록·서식 7종·기관 설정표·인수인계 한 쪽 안내에 **인쇄 CSS**(A4 세로, 머리글에 기관·기수·출력 시각, 표 머리 반복, 단추·안내문 숨김). PDF 는 기존 `pdf.ts`로.
- 글자 크기 조절(기본·크게 120%) 토글과 `prefers-reduced-motion` 존중. 터치는 고려하되 모바일 최적화는 범위 밖(관공서 PC 전제).

## 6. 피드백·도움·학습
- **빈 상태(empty state)** 마다 다음 행동 1개와 예시 열기 링크. **첫 사용 안내**는 모달 투어 대신 화면 안 설명 배너(닫으면 기억).
- 문맥 도움: 용어·조문·유권해석은 `?` 아이콘 팝오버로, 원문 보기는 펼침. 도움말 문장은 2문장 이내, 조문 번호 동반.
- 진행 피드백: 긴 처리(인수인계 zip·PDF)는 진행 표시·완료 패널, 실패는 원인·재시도 경로.
- 오류 메시지·안내문은 **한 벌의 문구 가이드**(존댓말·명사형 종결 혼용 금지·금지 표현 목록)로 통일하고 `rules.yml` 또는 별도 i18n 파일에 모은다.

## 7. 측정과 검증
- **휴리스틱 평가**(Nielsen 10 + 공공 웹 접근성 지침)를 화면 12개에 대해 표로: 위반·심각도(0~4)·수정안. 심각도 3 이상은 이번 범위에서 고친다.
- **인지 부하 측정 대리 지표**: 화면당 동시 노출 입력 필드 수·선택지 수·스크롤 길이(px)·주 행동까지 클릭 수를 before/after 표로.
- Playwright 시나리오를 과업 8개 기준으로 다시 쓰고(키보드 전용 변형 포함), axe 위반 0·대비 검사·`prefers-reduced-motion` 검사를 CI(`ui_audit.yml`)에 `/vat/` 화면 5개 추가.
- 운영자용 **수용 기준 체크리스트**(acceptance criteria)를 과업마다 Given/When/Then 형식으로.
