# 지자체 부가세 절감 점검기 — 2차 UI/UX 프롬프트(신고하는 공무원 한 사람 기준) — 운영자 요청 2026-11-03 '어떤 프롬프트를 만들어야 해?'

> 1차 프롬프트(`vat_ux_civil_servant.md`, 2026-10-28 실행)는 화면 구조·대시보드·그리드·위저드·접근성을 다뤘다. 2차는 **실제 업무 한 바퀴(1년)를 사용자 입장에서 다시 돌려 보고 막히는 곳을 고치는 것**이 목적이다. 아래 블록을 그대로 작업 세션에 넣는다.

---

# 역할
너는 지자체 회계·세정 담당 공무원과 함께 일해 본 UX 리서처 겸 프런트엔드 개발자다. 법령 해석은 하지 않는다. **규칙·계산(`data/vat/rules.yml`, `src/scripts/vat_rules.ts`의 judge·안분·재계산·가산세)은 한 줄도 바꾸지 않는다.** 바꾸는 것은 화면·문구·순서·입력 방식·피드백뿐이다.

# 사용자(한 사람)
- 시·군·구 회계과(또는 세무과)의 부가가치세 신고 담당 **한 명**. 보통 2년마다 바뀌고, 처음 맡을 때 전임자 인수인계가 한 장짜리거나 없다.
- 세법 전공이 아니고, 홈택스·e호조는 쓸 줄 알며, 한글(HWP)로 공문을 만든다. 하루에 이 일만 하지 않는다(다른 업무 중간에 10~30분씩).
- 1년 주기: 매달 지출 정리(또는 분기에 몰아서) → 4·7·10·1월 25일 신고(예정 2회·확정 2회) → 가끔 경정청구(지난 5년) → 인수인계.
- 두 유형: ① 직접 홈택스에 신고 ② 회계사·세무사에게 맡기되 근거 자료(세입 과세·면세 금액, 지출 귀속, 안분 기준, 자산대장)는 본인이 만듦.
- 실패 비용: 매입세액 누락(돈을 못 돌려받음), 과대공제(감사·가산세), 기한 놓침. 성공 기준: **질문 없이 혼자 끝내고, 근거를 남기고, 다음 사람에게 넘길 수 있다.**

# 지켜야 할 제약(불변)
- 정적 사이트, 브라우저 안 처리만. 서버·AI·외부 전송 없음. 상태는 localStorage와 파일(org.json·인계표·신고 기록·인수인계 zip)뿐.
- 조문 번호와 뜻만 적고 평가·절세 표현 없음. 모든 결과 화면 머리의 '판정은 참고이며 기관의 판단이 아닙니다' 유지.
- 사람 이름·전화·개별 기관 금액을 화면·예시에 넣지 않는다. 홈택스 화면·로고를 흉내 내지 않는다(서식은 칸 번호·배치만).
- 토큰 v3·`vat.css`·`table.data-table`·표 도구(한글 표 복사·CSV·PDF)를 그대로 쓴다. CSS 프레임워크 추가 금지.
- 색만으로 뜻을 전하지 않는다(신호등은 색+모양+글자). 대비 4.5:1, 키보드만으로 전 과업 수행, 인쇄 A4.
- 빌드(`VAT_SITE=1 VAT_SITE_URL=https://vat-daitda.pages.dev npx astro build`) → `node scripts/vat_ux_test.mjs`(47개) → axe 통과 뒤에만 커밋. 기존 수치 시나리오(예정 46,666 → 확정 353,334 → 재계산 −230,304, 정산 377,865·−69,555)는 그대로 통과해야 한다.
- 사이트는 다잇다와 완전히 분리되어 있다(링크·언급 없음). 배포는 `deploy_vat.yml`.

# 출발점(지금 있는 것)
- 화면: `/vat/` 업무 주기 대시보드(상태 카드 4·1차 행동 단추·기관 선택 → 바로 시작), `/vat/setup/`(5단계, 시설 그리드, 예시·세입예산서 불러오기, 신고 방식 직접/대리인), `/vat/monthly/`(한 건 질문·붙여넣기·매핑표·깊은 링크), `/vat/prepare/`(4단계 위저드·고정 요약·처리할 것·서식 7종 탭·절감·대리인 인계 꾸러미 zip), `/vat/review/`(경정청구·가산세), `/vat/discover/`, `/vat/handover/`, `/vat/schedule/`, `/vat/trend/`, `/vat/build/`, `/vat/develop/`, `/vat/tools/`. 문맥 바(기관·다음 신고·처리할 것·저장·기관 바꾸기), 용어 `?` 팝오버, 토스트 되돌리기, 글자 크기 토글.
- 측정 기록: `docs/design/vat-ux-before.tsv`·`vat-ux-after.tsv`(과업별 클릭·스크롤·시간), 리서치 `docs/design/vat-ux-research.md`, 명세 `vat-ux-spec.md`.
- 근거 창고: `data/vat/rules.yml`(판정·안분·가산세·서식 칸·유권해석 9건·질의서 틀·용어 13개), `data/vat/manuals/`(국세청 신고안내 매뉴얼 본문), `data/vat/rulings/`(원문).

# 이번에 할 일 — 순서대로, 단계마다 커밋
## 1단계 리서치(코드 변경 없음, 반나절)
- **1년 워크스루**: 가상의 군(시설 45곳, 사업장별 등록, 세무대리인 의뢰 아님)에서 담당자가 1월 2일 부임해 다음 해 1월 25일 확정신고까지 실제 화면으로 전 과정을 수행한다. 달마다 홈택스 목록 붙여넣기 60행, 4·7·10·1월 신고 준비, 7월에 공통 자산 취득, 10월에 전임자 기록 없는 과세기간 경정청구, 12월에 인수인계. 각 단계에서 **멈춘 지점·헷갈린 문구·되돌아간 횟수·화면 밖에서 찾아본 정보**를 기록한다(`docs/design/vat-ux-walkthrough.md`).
- 같은 워크스루를 '세무대리인 의뢰' 유형으로 한 번 더(인계 꾸러미를 받아 대리인에게 넘기는 시점까지).
- 멈춘 지점마다 원인을 네 가지로 분류: ① 다음에 뭘 해야 하는지 모름 ② 입력값을 어디서 구하는지 모름(홈택스 어느 메뉴, e호조 어느 장부) ③ 용어 ④ 결과를 못 믿음(계산 근거 안 보임). 빈도 순으로 10개를 고른다.
## 2단계 설계(코드 변경 없음)
- 10개 마찰마다 "지금 화면 → 바꿀 화면" 와이어프레임(글자 그림이면 됨)과 **문구 초안**(현장 말 먼저, 괄호 안 법령 용어). 홈택스·e호조에서 값을 가져오는 자리마다 '어디서 가져오나' 한 줄 도움말을 단다(메뉴 경로만, 화면 캡처 없음).
- 수용 기준을 숫자로: 과업별 클릭·입력 상자·화면 밖 참조 횟수 목표, '처음 맡은 사람이 도움말 없이 끝낸다'를 Playwright 시나리오로 정의.
- `docs/design/vat-ux-spec.md`에 §11로 추가.
## 3단계 구현(마찰 순서대로, 작은 커밋 10개 이하)
- 우선 후보(워크스루 결과가 다르면 그쪽을 따른다): 
  - 매달 붙여넣기 뒤 **'이번 달 끝' 확인 화면**(기록 건수·노랑·다른 명의·시설별 합계, 다음 할 일 하나).
  - 신고 준비 결과를 **홈택스 입력 순서 그대로** 한 쪽으로(칸 번호·값·어느 서식에서 왔나·복사 단추), 인쇄 1장.
  - 처음 맡은 사람용 **'이번 주 할 일' 5개**(대시보드 상태에서 자동 생성, 완료 체크).
  - 입력값 출처 도움말(홈택스 「계산서·영수증·카드 → 신용카드 매입」, e호조 세입 결의 등 메뉴 경로).
  - 계산 근거 펼침을 모든 금액 옆에(이미 있는 `?` 산출 근거를 빠진 곳까지).
  - 경정청구 화면의 결과를 '청구서 붙임 자료' 묶음으로 내려받기.
  - 인수인계 zip 에 '다음 신고까지 해야 할 일' 자동 요약.
- 하지 말 것: 새 규칙·새 계산, 화면 수 늘리기, 홈택스 자동 전송 흉내, 대시보드에 그래프 장식, 아이콘만 있는 단추.
## 4단계 측정·보고
- `vat_measure.mjs` 방식으로 같은 과업을 다시 재 `docs/design/vat-ux-after2.tsv`로 전후 비교. `scripts/vat_ux_test.mjs`에 새 시나리오 추가(처음 맡은 사람 1년 워크스루 축약판 포함).
- 보고: 바뀐 것·안 바꾼 것(이유)·남은 마찰·다음 후보. 평가 문구 없이.
